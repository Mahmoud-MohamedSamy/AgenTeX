TAVI CRM go-live · Round 2 · A14 Google Sheets sync

Google Sheets test cases

For manual testing · 27 Oct 2026 · staging-crm.taviportal.com · Settings › Integrations › Google Sheets (/settings/integrations/google-sheets)

Built from what the app contains: connections with a Google service-account key and a spreadsheet link, tab mappings (sheet tab → CRM module, columns → fields), a preview of each tab, Verify, manual Sync, pause and resume, sync runs with their errors, cancel a run, edit and delete. Zoho has no built-in equivalent, so there's no Zoho comparison.

Before you start

  • A Google Cloud service account with the Google Sheets API enabled, and its JSON key file.
  • A test spreadsheet shared with the service account's email (Editor). Tabs: Leads with columns Full Name, Phone, Email, Company, and Bad rows with a few invalid rows (empty Full Name, phone "abc", a duplicate row).
  • Names start with QA GS so they can be found and deleted afterwards. Use the owner or a CRM Admin.
  • Note the time of each sync; the run list should show the same time.

Connection

IDStepsExpected
GS-01Open Settings › Integrations › Google Sheets with no connection.Empty state "No Google spreadsheets connected yet" with a way to add one.
GS-02New connection: name "QA GS 1", paste the spreadsheet link, upload the service-account key, save."Connection created", then "Service account key saved". The connection is listed.
GS-03Click Verify on the connection.Success: the spreadsheet is reachable and its tabs can be read.
GS-04New connection with a link that isn't a spreadsheet (e.g. a Google Doc) or a random URL.Refused with a clear message; nothing saved.
GS-05New connection to a spreadsheet NOT shared with the service account, then Verify.Clear "no access / share the sheet with …" message; no raw error text.
GS-06Upload a file that isn't a service-account key (e.g. any other JSON) as the key.Refused with a clear message; the old key, if any, still works.
GS-07Open the connection again and look at the saved key.The secret is never shown in full (masked or "key saved"); only who/when or the service-account email.
GS-08Edit the connection name and save."Connection saved"; the new name shows in the list.

Tabs and mapping

IDStepsExpected
GS-09Open the connection's setup: list the spreadsheet tabs.Both tabs (Leads, Bad rows) are listed by name.
GS-10Preview the Leads tab.The header row and the first rows are shown as in Google Sheets (Arabic text and emoji too).
GS-11Map tab Leads → module Leads; map each column to a field (Full Name → Full Name, Phone → Phone, Email → Email, Company → Company). Save."Tab mappings saved"; the mapping is shown again after reload.
GS-12Try to save a mapping that leaves a required field (Full Name, Phone) unmapped.Refused or clearly warned before saving.
GS-13Map two columns to the same field.Refused or clearly warned.
GS-14Rename a column in Google Sheets, then open the mapping again.The broken column is flagged; the sync does not silently drop the data.

Sync runs

IDStepsExpected
GS-15Click Sync on the connection.A run starts and finishes; the run list shows time, status and counts (created / updated / failed).
GS-16Open Leads in the CRM and search the QA GS rows.One lead per sheet row, with every mapped value correct (check Arabic and phone format).
GS-17Sync again without changing the sheet.No duplicate leads (rows are updated or skipped, not created twice).
GS-18Change one cell (e.g. Company) in the sheet, sync.The matching lead is updated; the lead's timeline shows the change.
GS-19Add a new row in the sheet, sync.One new lead is created.
GS-20Delete a row in the sheet, sync.Note what happens to the lead (kept, or removed) — record it; the run summary should say.
GS-21Edit a synced lead in the CRM, sync, then look at the sheet.Note which side wins; nothing is lost silently. (Tells us whether sync is one-way or two-way.)
GS-22Map the "Bad rows" tab to Leads and sync.Valid rows are created; each bad row is listed under the run's errors with the row number and the reason.
GS-23Start a sync of a larger tab (200+ rows) and click Cancel on the run while it is running."Cancelling the sync…", the run ends as cancelled, and its counts show what was done before the cancel.
GS-24Check the leads created by the sync for workflow / assignment rules.Note whether rules ran on synced leads (like an import) and which source the lead shows.

Pause, delete, permissions

IDStepsExpected
GS-25Pause the connection, change the sheet, wait, then look for automatic syncs."Sync paused"; no run happens while paused; manual Sync is blocked or clearly warned.
GS-26Resume the connection."Sync resumed"; the next sync runs normally.
GS-27Remove the service account's access to the sheet in Google, then sync.The run fails with a clear message; the connection shows it needs attention.
GS-28Sign in as a normal user (test user 1) and open the Google Sheets page and its URL directly.No access (hidden in Setup and refused by URL), unless the profile has the integration permission.
GS-29Delete the connection.Asks to confirm; "Connection deleted"; it is gone from the list. Note whether leads it created stay (they should).
GS-30Check Settings › Audit Log for the connection's create, key save, sync and delete.Each change is logged with who and when.
