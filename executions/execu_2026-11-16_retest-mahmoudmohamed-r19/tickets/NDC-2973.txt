# NDC-2973 Workflow Rules | Owner Assignment action assigns suspended agents and agents outside the department
Summary
A workflow Owner Assignment does not check whether the agent can own the ticket. It assigns an agent who is suspended or not in the ticket department, which manual assign refuses. When it does skip a suspended agent, the run still says Fired with no reason.
Steps to Reproduce
- Create a rule On Create for Tickets with an Owner Assignment action to a specific agent who is not a member of the ticket department.
- Suspend that agent (Agents, or PATCH /api/v1/iam/users/{id} with status suspended).
- Create a matching ticket and open it, then open Execution History.
- Add the agent to the department, keep them suspended, and create another matching ticket.
- For comparison, assign the same agent to a ticket by hand.
Expected Result
- The action refuses an agent who is suspended or not in the ticket department, the same way manual assign does.
- Execution History marks the action Failed and shows the reason (for example: agent is not an active agent of the department).
Actual Result
- Agent not in the department, suspended: the ticket is assigned to them; Execution History: Fired.
- Agent in the department, suspended: the ticket is left unassigned, but Execution History says Fired with no error and no action result.
- Manual assign refuses both: HTTP 422 "User … is not an active agent of the ticket's department."
- The ticket itself stays usable.
Environment
staging-desk.taviportal.com (NDC-Staging), Microsoft Edge, Windows 10, owner account, 11–12 Nov 2026.
