# NDC-3031 Blueprint | A continuous blueprint does not run the next step by itself
Summary
A blueprint marked as continuous behaves like a normal one: after a transition, the next transition (which asks for nothing) does not run on its own.
Steps to Reproduce
- Create a blueprint with Advanced configuration = Continuous: Open → Escalated ("first", one checklist item) → On Hold ("auto", no items) → Closed.
- Create a matching ticket and run "first".
- Wait and look at the ticket.
Expected Result
- As soon as "first" completes, "auto" runs by itself and the ticket moves to On Hold.
Actual Result
- The ticket stays in Escalated ("In Escalated for 2 minutes"); "QA auto" waits for a click (checked after 30 s and 2 min; also seen 12 Nov).
- The blueprint shows Advanced configuration "Continuous" (continuous: true is stored).
Zoho Desk
Create Blueprint › "Is this a continuous Blueprint?": "In a continuous Blueprint, the next transition is automatically triggered as soon as the current transition is completed." (setting text seen live; a continuous run was not done in Zoho).
Note
Spec row J15.
Environment
staging-desk.taviportal.com (NDC-Staging), Microsoft Edge, Windows 10, owner account, 12–13 Nov 2026. Compared live with Zoho Desk (test account techsolutionsegypt; test blueprint deleted afterwards).
