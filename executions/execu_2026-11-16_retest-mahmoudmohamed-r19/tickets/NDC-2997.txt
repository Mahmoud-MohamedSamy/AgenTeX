# NDC-2997 Workflow Rules | Owner Assignment by role (round robin) never assigns anyone
Summary
A workflow rule that assigns the ticket owner by role in round robin sets no owner, even when an agent of that role is online and in the ticket department. The run is still logged as Fired, with no result or reason for the owner action.
Steps to Reproduce
- Create a rule On Create for Tickets, condition Priority is Urgent, with actions: Owner Assignment › Roles › CEO (round robin), Add Tags, Task, and Email to the ticket owner.
- Make sure an agent of that role who belongs to the ticket department is online (Test User 1).
- Create two or more urgent tickets, some with no owner.
- Open each ticket and Execution History.
Expected Result
- Each matching ticket gets an owner from the role, taking turns between the role agents.
- If no agent can be assigned, the owner action is marked Failed with the reason.
Actual Result
- On 6 urgent tickets no owner was set (it stayed the creator or empty); ticket history shows no owner change.
- Add Tags, Task and Email in the same rule all Succeeded.
- Execution History: Fired, one row per ticket; the Owner Assignment action has no result and no reason.
- Owner Assignment to a specific user works (control).
Note
Also seen in case I8 of the workflow run (old B-9). Related: NDC-2204 (role list content).
Environment
staging-desk.taviportal.com (NDC-Staging), Microsoft Edge, Windows 10, owner account, 11–12 Nov 2026.
