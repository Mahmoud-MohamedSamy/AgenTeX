# NDC-3037 Blueprint | A transition owner that does not exist is accepted and shown as a raw id
Summary
The blueprints API accepts a transition owner user id that does not exist; the designer then shows the raw id as an "Agent" owner.
Steps to Reproduce
- Save a blueprint through POST /api/v1/modules/{tickets}/blueprints with before.allowedUserIds = [a random UUID].
- Open the blueprint and click the transition › Before.
Expected Result
- Refused, like an owner id from another tenant (which is refused correctly).
Actual Result
- HTTP 201; the id is stored.
- Designer › Who can run this: "5327d6ce-320e-4039-8c1a-95edb4cb2d4f · Agent".
Note
Same kind of problem as NDC-2999 (Workflow Rules). Spec row N3.
Environment
staging-desk.taviportal.com (NDC-Staging), Microsoft Edge, Windows 10, owner account, 12–13 Nov 2026.
