Findings

Bug

Blueprint approval step does not hold the transition

Running a transition that has a "Submit for approval" step moves the ticket to the target state and runs the after-transition actions at once, before anyone decides. Approving then changes nothing. Rejecting leaves the ticket in the target state with the after-actions applied, and the requester cannot run the transition again (409 state changed). Expected: the ticket waits in its current state; approve completes the move and runs the after-actions; reject keeps it where it was. Seen on QA PA bp 7 and bp 8 (On Hold -> Escalated).

Bug

Ticket approval can be rejected without a reason

The single Reject dialog labels the field "Comment (optional)" and Reject stays enabled when it is empty, 2 characters or spaces. The API also accepts no comment, null, "", "ab" or spaces and rejects the request. Bulk reject and on-behalf reject do require 3 to 2000 characters. Requirement PA-ACT-2: a reason of 3 to 2000 characters is required.

E3
Bug

Requester can cancel a blueprint approval

Blueprint items in Requested by me show "Cancel request" and the cancel call returns 200. PA-ACT-6: blueprint items end only by revoking the transition on the ticket (the page even has a message for this case).

E17
Finding

Agent can choose any approver when running a blueprint approval step

The step is set up with approver B, but the run accepted approver D instead (approval saved with D). The step's approvers are not enforced.

H (extra)
Finding

Web form reject reason allows 1 to 1000 characters

"ab" is accepted for a web form rejection; the requirement and ticket approvals use 3 to 2000.
