Description (as it will appear)

Summary

GET /api/v1/iam/users always returns the same 200 users. It ignores every paging and filter parameter, and the response has no total and no next-page link (meta is null). Owner, agent and team pickers that load users from this list cannot reach user 201 and up. NDC runs 478 active agents (886 in total) in its Zoho Desk.

Steps

  1. Sign in to Desk staging as ndc-staging-owner (NDC-Staging tenant).
  2. Call GET /api/v1/iam/users.
  3. Call it again with ?page=2, ?pageSize=5, ?page=2&pageSize=100, ?limit=5&offset=5, ?cursor=x, ?search=a, ?status=invited and ?status=active.

Expected

  • Paging works: pageSize limits the rows, page / offset / cursor move through the list, and the response gives a total or a next-page link.
  • search and status filter the list.
  • Every user in the tenant can be reached, so pickers work for 478+ agents.

Actual

  • Every call returns the same 200 rows (121 active + 79 invited), the same first and last user, and meta = null.
  • pageSize=5 still returns 200 rows; status=invited still returns the 121 active users too; search is ignored.
  • /iam/users/search, /count and /summary return 405.

Note

The NDC-Staging tenant has exactly 200 users today, so a 201st user being left out has not been seen yet. Proving it needs one more user in the tenant. The paging and filter parameters being ignored is seen now.

Environment

  • staging-desk.taviportal.com, NDC-Staging tenant, 9 Nov 2026 (first seen 2 Nov 2026).
  • NDC Zoho Desk reference: 886 agents, 478 active, read-only 2 Nov 2026.
