Missing compared with Zoho 10 items

The first five are features TAVI does not have. The last three are Zoho checks that TAVI lacks, and each is also listed as a bug above.

  • Z1CRMThe primary field can only be a choice field (pick list, radio, checkbox, status, user). Zoho CRM also allows single line, currency, email and others. Confirmed live with Designation, Annual Revenue and Email.
  • Z2DeskThe Desk primary field can only be a pick list, checkbox, status, user, department or team. Zoho Desk also allows text, number, date and email fields.
  • G21CRMA record cannot be moved to another layout. The edit page has no layout picker and PATCH with layout_id is ignored. Zoho has a Layout dropdown on edit, and the new layout's rules apply.
  • Z5CRMBlueprint transitions do not run layout-rule "mandatory" (see B-04). Zoho shows those fields in the transition form.
  • A6CRMNo permission lets a non-admin manage layout rules. Giving profile User metadata.modules.manage still gives 403; only metadata.acl.manage (global Admin) works. Zoho has a profile permission (Customize / Manage Layouts and Fields) for this.
  • Z9DeskApply to Help Center does not require the primary field on the Help Center form. A form without it saves with no warning, and the rule silently does nothing there. Zoho Desk requires the primary field to be visible in the Help Center.
  • Z11CRMSuggest and verify pop-ups are not remembered. TAVI shows them again to every user after someone pressed Ignore. Zoho shows them only until one user acts.
  • Z6BothMass update of a rule's primary field is not blocked (see B-01).
  • Z8BothSome setup checks Zoho has are missing: set and suggest on one field, and mandatory and read-only on one field (see B-16). The "one active rule per primary field" check matches Zoho.
  • Z12BothA typed value in a field that becomes hidden is not kept on create (see B-14).

Notes: worth knowing (not bugs) 32 cases

These are behaviour differences, limits and environment notes. Where TAVI does more than Zoho, that is a TAVI extra, not a bug.

  • A5API: low-privilege user reading rules Both
    CRM: CRM User can GET the list, one rule and rule-usage (200) — needed so the form runs rules for that user Desk: Desk Admin second account reads list/get/rule-usage 200
  • C3Name length and spaces Both
    CRM: Name max 200 chars (201 refused 'A rule name may be at most 200 characters.'); spaces-only refused; Zoho Desk max 100 — TAVI longer (extra) Desk: Name max 200 chars (201 refused 'A rule name may be at most 200 characters.'); spaces-only refused; Zoho Desk max 100 — TAVI longer (extra)
  • C4Duplicate rule name Both
    CRM: Same rule name twice on one layout (different primary) allowed Desk: Same rule name twice on one layout (different primary) allowed
  • C9Change the layout after building conditions Both
    Changing the layout of a built rule clears the primary field and every condition at once, with no warning (not flagged per target). Save is blocked 'Fix the highlighted problems before saving'; Cancel keeps the stored rule unchanged. Zoho does not allow changing a rule's layout after creation. crm-C9.png
  • D13Several conditions: first match vs all matches Both
    CRM: Gold matches branch 1 (show reason) AND branch 2 (in Gold,Silver -> note mandatory): BOTH applied. TAVI runs every matching condition; Zoho CRM doc says topmost matching wins. Compare live (Z) Desk: tier Gold: branch 1 (show reason) and branch 2 (note mandatory) both applied — every matching condition runs (same as CRM)
  • E9Fields that cannot be made mandatory Both
    No system / auto-number / read-only field is on the QA layout, so the 'cannot be made mandatory' state could not be shown. The mandatory picker lists the layout's 25 fields; API refuses 'Auto Number' as 'not on this layout' (422).
  • E10Show fields across sections Both
    tier Gold shows order (Sec A) and reason (Sec B): order shows in Sec A; reason stays hidden because Sec B itself is hidden by the basic rule (shown only for Question/Partner). Fields shown by one rule inside a section hidden by another rule stay hidden. Form sections are not collapsible. crm-E10.png
  • F1Show subforms CRM
    QA layout has no subform; 'Show subforms' is still offered in the action list and its picker is empty (Zoho offers it only when the layout has a subform). Subform hide/show not testable.
  • F7Read-only: "Editable for profiles" CRM
    Owner has no CRM profile, so 'Editable for profiles' could not be shown working; needs a user with a listed profile
  • F12Set a value on each field type CRM
    set_value type checked ('Expected number value for datatype number'); option not in field refused for filter_options
  • F14Suggest after Ignore CRM
    Owner pressed Ignore on 'Suggested: 42' and saved; reopening the record shows the suggestion again for the owner, and the CRM User also gets it on the same record. TAVI does not remember the decision. crm-F14-owner.png crm-F14-low.png
  • F21Show related lists CRM
    Show related lists saved (relatedLists ['contacts:lookup']), but the Leads record page shows no related-list sections at all (only Notes, Activities, Customer Portal, Recent activity), so hiding/showing can't be observed. The picker lists module relations with many duplicates ('Leads (Lookup 2)' / 'Leads (Multi-Select Lookup)' repeated 7 times) and no Notes entry. crm-F21-editor.png

Environment and test data

Run on NDC-Staging with the owner account, a CRM User account (profile User) and a second Desk Administrator account. Zoho writes were made only in the Zoho CRM test org and the Zoho Desk test account. NDC's real Zoho was not touched, and neither were the 7 "QA NDC" Desk rules.

All test data uses the prefix "QA LR1112". It is listed in ledger.md: fields, layouts, rules, records, buttons, links, a map dependency, a validation rule, a Blueprint, a web form, field permissions, and Zoho rules and leads. All of it was deleted on 12 Nov after the run, and this run's TAVI Recycle Bin items were purged by exact id. Final check: CRM has 0 layout rules, Desk Tickets has only the 7 "QA NDC" rules, and User profile permissions match the backup. In the Zoho test org, the 4 QA rules and 3 QA leads were deleted. Staging was down from 11:35 to 12:30 UTC, and no data was lost.
