# NDC-2999 Workflow Rules | Owner Assignment action saves any role or user value, even "x"
Summary
The rules API does not check the target of an Owner Assignment action. A role round robin with role "x" or a role id that does not exist, and a specific user "x", are all saved.
Steps to Reproduce
- Send POST /api/v1/workflow/rules with an Owner Assignment action: ownerTargetKind RoleRoundRobin, ownerValue "x".
- Repeat with ownerValue 11111111-2222-3333-4444-555555555555 (no such role).
- Repeat with ownerTargetKind SpecificUser, ownerValue "x".
Expected Result
- Each is refused with a clear message: the role or user must exist.
Actual Result
- All three: HTTP 201, the rule is saved.
- For comparison, an unknown trigger field is refused (400 "Unknown field(s)").
Environment
staging-desk.taviportal.com (NDC-Staging), Microsoft Edge, Windows 10, owner account, 11–12 Nov 2026.
