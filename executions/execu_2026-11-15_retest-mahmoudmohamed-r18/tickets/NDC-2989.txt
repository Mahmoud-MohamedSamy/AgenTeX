# NDC-2989 Layout Rules | Conflicting actions on one field are accepted
Summary
Conflicting actions on one field are accepted. Both are saved (201).
Environment
- NDC-Staging (staging-crm.taviportal.com and staging-desk.taviportal.com), Chromium, 12 November 2026, admin account.
- Leads layout "QA LR1112 Layout" with test fields type (Refund, Question, Partner, Other), tier, filter (pick lists), order, note, reason (text), vip (checkbox), radio, date and email2; the same setup on Desk Tickets. Test data was deleted after the run.
Steps to reproduce
- In one condition add set value + suggest value on the same field.
- In another, add mandatory + read-only on the same field.
Expected result
Zoho refuses both setups (checked live: INVALID_DATA for read-only on a field already mandatory).
Actual result
- Both are saved (201).
Notes
- Test cases F15, F16, Z8 in the Layout Rules test sheet (https://claude.ai/artifact/PUdj9axtAjCR8UQpegu5qC).
- CRM and Desk share the same rule engine, so this applies to both apps.
