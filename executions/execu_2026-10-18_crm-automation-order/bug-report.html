Before you start

  • Staging (staging-crm.taviportal.com, tenant NDC-Staging). Leads module unless the bug says otherwise.
  • Avoid Lead Status "Interested", Tasks Status "Completed", and names containing "AP" or "AEX-01": teammates' active rules fire on them.
  • Only one review process is allowed per module + layout. If the Standard layout already has one, use a separate layout.
  • Steps name the screen first. Where the screen does not expose a setting or a result, the API call is given in brackets.
B-01 · D-21 / H-03 High (suggested) Approval

A lead waiting for approval can be converted

While a lead is pending approval, Delete is correctly refused (422 APPROVAL_LOCKED), but Convert goes through: a Contact and a Subscription are created and the lead stays "pending approval". The approver then approves or rejects a lead that has already been converted.

Steps to reproduce

  1. Settings → Approval Processes → create a process on Leads: trigger On Create, criteria Last Name starts with "B01", approver = a named user (e.g. a CRM Admin).
  2. Log in as a User-profile account and create a lead with Last Name "B01 test". Its approval status becomes Pending approval.
  3. Try to Delete the lead → refused with APPROVAL_LOCKED (correct; this is the control).
  4. Click Convert on the same lead and confirm (API: POST /modules/{leads}/records/{id}/convert with {}).
  5. Open the lead and the new Contact / Subscription; check the lead's approval status.
Expected (Zoho)
Convert is disabled while the record waits for approval, like Delete (Zoho approval FAQ Q9).
Actual (TAVI)
Delete 422 APPROVAL_LOCKED; Convert 200 with Contact + Subscription created. Same for valafo4080 and mmohamed on 18 Oct.

B-02 · H-02 High (suggested) Review

A lead held for review can be converted

A lead held by a review process is locked for editing (422 REVIEW_LOCKED), yet it can be converted. The review is still pending afterwards, so the reviewer reviews data that already left the lead. The converted lead also could not be deleted afterwards (REVIEW_LOCKED) until the review was rejected by hand.

Steps to reproduce

  1. Settings → Review Process → create a process on Leads: channel Manual, field set Email, rule All records, reviewer = a CRM Admin.
  2. As a User-profile account, create a lead with an Email. Review status becomes Pending for review.
  3. Try to edit any field → refused with REVIEW_LOCKED (correct; this is the control).
  4. Click Convert on the lead and confirm.
  5. Check the review status of the lead, then try to delete the converted lead.
Expected (Zoho)
Records under review are locked and kept out of the list; no conversion until the review is complete (Zoho review process).
Actual (TAVI)
Edit 422 REVIEW_LOCKED; Convert 200, records created, review still pending.

B-04 · F-03 Medium (suggested) Assignment → Approval

Approver "Record Owner" ignores the owner set by the assignment rule on import

An imported lead is assigned by the rule, but the approval process resolves "Record Owner" without that owner: the approval goes to the process admin (on 18 Oct the importer, who was the process admin). The assigned owner sees canApprove:false. With the owner set directly on create, "Record Owner" works.

Steps to reproduce

  1. Create an assignment rule on Leads: channel Import, criteria Last Name starts with "B04", assign to user X (a CRM Admin).
  2. Create an approval process on Leads: On Create, same criteria, approver = Record Owner, process admin = a different user Y.
  3. As a third user, import a CSV with one lead "B04 test" and choose the rule from step 1. The lead's owner becomes X.
  4. Log in as X and open the lead (API: GET /workflow/approvals/records/{leads}/{id}).
  5. Control: create a lead with the owner set to X directly; X is the approver.
Expected (Zoho)
Assignment runs first, so the assigned owner is the approver (Zoho approval FAQ Q34).
Actual (TAVI)
currentApprovers = process admin; owner cannot approve. Control lead with Owner set at create: owner is the approver.
