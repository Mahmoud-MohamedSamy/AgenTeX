B-EM1 — Workflow rules don't run after a blueprint transition that saves fields High

Impact: the Committee hand-over never happens, and any rule that reacts to these transitions is silently skipped.

What happens

A rule with trigger RecordUpdated and criteria application_status = "Assessment Complete" AND application_status CHANGED is never evaluated when the status reaches Assessment Complete through the transition «اعتماد الفيديو». GET /workflow/executions has no entry for that event, for this rule or any other, and the owner stays unchanged.

The same rule shape does run after a transition with no required fields. After «قبول التسجيل» (Pending Verification → Registration Approved), N02 (application_status = "Registration Approved" AND CHANGED) runs every time and is logged as RecordUpdated … Fired.

B-EM2 — Workflow field update is sometimes lost when several records update at the same moment High

Impact: an application can stay at "Registration Approved" with its video link saved. No assessor is assigned, no error is shown, and nobody notices.

What happens

Rule N04 runs when the video link is saved. Its log entry shows Fired and its email dispatch Succeeded, but for some records its FieldUpdate (status → Video Submitted, video_submitted_at → now) is not applied:

  • The status stays Registration Approved and video_submitted_at stays empty.
  • errorMessage is null, and the FieldUpdate leaves no trace in dispatches.
  • The next rules (category owner and «إسناد التقييم») never run.

It happened only when 9 records were updated within the same few seconds, and not every time.

Rule involved

Rule 7f6fe481-e4d2-4a74-85e4-280a42c35e35 إبهار مصر — تقديم رابط الفيديو (N04):

  • Trigger: RecordUpdated
  • Criteria: submission_link IsNotNull AND submission_link CHANGED AND application_status IN (Registration Approved, Profile Accessed, Action Required)
  • Action 1: FieldUpdate application_status = "Video Submitted", video_submitted_at = ${now}. The status is governed by the blueprint, so this runs as the automatic transition t-sys-video-1.
  • Action 2: Email, template eea43ccc-f3cd-460d-9dda-511d32728d25.

Steps to reproduce

  1. Create 9 records with category = الفنون, status Pending Verification.
  2. Run t-approve-registration on all 9 and wait until each has portal access.
  3. Send 9 PATCH /modules/{M}/records/{id} with {"data":[{"field":"submission_link","value":{"kind":"string","value":"https://youtu.be/x-N"}}]} in parallel, within about 3–5 s.
  4. After 60–90 s. Expected: all 9 at Assessment Assigned, with an Arts assessor as owner. Actual: some stay at Registration Approved.

Likely area (to confirm)

The FieldUpdate on the governed field runs as an automatic blueprint transition. Under concurrent load that write seems to fail (for example a row-version or lock conflict, or a state check against a stale snapshot), and the failure is swallowed: the rule is still logged as Fired and the email still goes. Please check the server logs for EM-00075 / 76 / 77 / 79 / 81 around 15:36:40 UTC.

Expected behaviour

  1. The update is applied reliably under concurrent updates, retrying on a conflict.
  2. If it really fails, the execution is logged as failed with the error, and the rule doesn't report success.
