What

HighDeal pipeline cannot be set or changed through the record API (root cause of NDC-1302, 1312, 1316, 1324)

What
"pipeline" is not a field of the Deals module (absent from GET /modules/{Deals}/fields) and the record write path ignores it: creates always land on the layout's default pipeline; updates never move a deal.
Repro
POST deal with pipeline "1" as data[].pipeline (UI shape), top-level pipeline_id, top-level pipelineId, or data[].pipeline_id → all 201, stored on Standard. PATCH a deal imported onto "1" with pipeline = Standard → 200, still on "1". Stage validation then runs against the stored pipeline, giving "Stage … is not part of the 'Standard' pipeline".
Works
Import (pipeline column) and pipeline delete-with-transfer are the only paths that set a deal's pipeline.

HighCRM layout builder: Save is silently lost when the layout save is slow (NDC-1444)

What
On Leads layouts a layout PUT takes 14–18 s. When a Rollup Summary is added, the builder sends PUT /modules/{Leads}/layouts/{id}, the request never completes in the browser, no error is shown, and the layout is unchanged (field left in Unused Fields).
Repro
Own copy "QA RT layout": (A) add a Single Line field → POST field 201, layout PUT 200, saved. (B) add Rollup Deals › Connected To › Amount › Sum → POST field 201, layout PUT sent, no response, layout lastModifiedAt unchanged. Replaying B's PUT by API with a 3-minute timeout → 200 after 14 s and the rollup is placed.
Likely cause
Client gives up on (or cancels) slow layout saves without an error; the server accepts the same payload when given time. Also slow: a 525-field layout PUT on Desk needed 55 s.
Side note
Every builder Save (CRM and Desk) also re-PUTs 2–4 untouched fields (lookups) before the layout PUT.
