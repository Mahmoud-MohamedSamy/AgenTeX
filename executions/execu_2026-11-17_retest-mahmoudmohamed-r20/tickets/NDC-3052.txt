# NDC-3052 Workflow Rules | Create Record still creates a record missing required fields at run time
Summary: a workflow rule's Create Record can still create a record that lacks a field the target module requires, and the run says Succeeded. Saving now refuses such an action (NDC-2968), but two cases get past the save:
- A Create Record saved before the NDC-2968 fix, which still runs as it was saved. On staging, QA's NDC-Staging tenant has 8 such actions in 7 rules and 1 saved action.
- A field mapped to a placeholder (for example the ticket's Contact) whose value is empty on the record the rule runs on.
Expected: when the record would be missing a required field, the action ends Failed in Execution History, naming the fields (for example "Not created: Calls needs Subject, Contact Name."), and no record is created.
Actual: the record is created without the field, and the action is Succeeded.
Notes:
- The required fields are the ones the save check already uses: metadata-engine's verdict for a create through the action's layout, or the module's default layout.
- Two places could do it: workflow checking the rendered values just before it creates the record, or metadata-engine's internal create enforcing Required for records an automation creates. The second also covers other automations.
- Applies to Create Record and Create Connected Record, in Desk and CRM rules.
- Related: NDC-2968 (save-time check, live on staging since 2026-11-15).
