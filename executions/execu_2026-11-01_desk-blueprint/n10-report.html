N10 — Blueprint reply on a chat ticket

TAVI Desk vs Zoho Desk · staging-desk.taviportal.com, org NDC-Staging, department Customer Support · tested 3 Nov 2026 · spec row N10 · not filed yet
DIFFERS FROM ZOHO
On a ticket that came from a live chat, a blueprint step that requires a reply sends that reply as an email, not back into the chat. In Zoho Desk the same step opens the IM reply, so the answer goes to the conversation the customer started. The step itself works; only the reply's destination is wrong.

TAVI vs Zoho

Zoho side from the intake research and the spec, not a live Zoho check: the Zoho trial org has no IM channel.

Zoho Desk

  • The step opens the IM reply box; the agent answers in the chat.
  • The customer sees the answer in the chat they started.
  • A visitor who left no email can still be answered.
  • The ticket records an IM message in the conversation.

TAVI Desk

  • The step asks for email recipients; there is no chat reply.
  • The customer gets an email at the contact's address.
  • A visitor with no email blocks the step.
  • The ticket shows an email reply; no "Instant message sent" history.

How it was tested

Live chat and IM live in the separate Omni Channel app; Desk links to it per department. NDC-Staging has one enabled chat widget, "NDC Staging", which no Desk department used before this test.

  1. Linked Customer Support's Live chat widget to "NDC Staging" (PUT /desk/departments/{id}/channels).
  2. Loaded the widget's embed code on a local test page at http://127.0.0.1:5500, an origin the widget allows.
  3. As a visitor: chose English, then "Connect with a human", and sent "QA BP N10 test - please ignore". No operator was online, so the chat was queued as missed.
  4. Converted the chat with the action behind Omni Channel's "Convert to Desk ticket" dialog (POST /salesiq/conversations/{id}/desk-ticket). First refused with missing_identity (anonymous visitor); after giving the visitor a placeholder email (qa-bp-n10@example.com, a reserved address) it created ticket #889 in Customer Support, Channel = chat.
  5. Created a QA blueprint whose step requires a reply, added #889 to it, and ran the step through the same API the ticket page uses.

Limits and checks before filing

Two checks would make this ready to file; both need one more QA chat and ticket, cleaned up the same way.

  • LIMIT Run by API, not on the ticket page: a chat option in the step form is not ruled out, though the server accepting only email recipients makes it unlikely.
  • LIMIT No operator joined the chat (it stayed "missed"); routing after an operator accepts it was not checked.
  • LIMIT Zoho not checked live.
  • TO DO Control: an ordinary agent reply on a chat ticket, outside any blueprint. If it also goes out by email, the gap is in Desk's chat tickets in general, not in blueprints.
  • TO DO Screenshot of the blueprint step form on a chat ticket, then file with an annotated image (TAVI email reply vs empty chat).
