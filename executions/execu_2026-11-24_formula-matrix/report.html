New bugs (4)

1. Formula field | Formulas treat a User field as empty when it was filled in by its default value

MediumCRM only

A User field is filled automatically with the signed-in user (create form, API create without the field, and import). The record shows the user, but every formula reading it calculates as if it were empty: isblank = true, if(isblank…) = "empty", len = 0, X - 1 = −1. Choosing the user by hand gives correct results. Desk is not affected — the same test on Desk gives isblank = false.

Seen on: CRM "QA FX Matrix 2 - all empty", "QA FX matrix - all empty", "QA FX Matrix - imported" (17 formulas each).

2. Modules and Fields | A record cannot be edited when its layout has a Rollup Summary field

HighCRM + Desk

The Edit form shows the Rollup Summary as an input box and sends its value on Save. The server refuses the whole save: "Field 'in_rollup_summary' uses read-only datatype 'rollup_summary' and cannot be set by clients." Nothing is saved. Creating a record works (the empty rollup is not sent). Seen on CRM "QA FX matrix - edge values" and Desk "QA FX matrix - edge values".

3. Formula field | The + operator joins text instead of adding (date + 1 gives "2026-11-241")

MediumCRM (Desk shares the engine — not run there)

When the left side is not a number, + silently glues the text: Pick List + 1 → "Green1", Date + 1 → "2026-11-241", Date Time + 1 → "2026-11-24T21:30:00Z1", Auto Number + 1 → "MX-0011"; the formula's return type is Number. -, *, / on the same fields give blank. Expected: add for numbers (and days for dates, like Zoho's date arithmetic), or refuse the formula — never a glued text. Affects every non-number field type.

4. Import | A Lookup column cannot be matched by the record name

MediumCRM

Importing into a module with a Lookup to Accounts: the value "QA FX Matrix Acc" and the value "Anyware Software" (a normal account) are both refused — "No existing record matches 'Anyware Software'." — although both accounts exist with exactly that Account Name. The row is not created. Import sessions a038b54f… and the "Anyware Software" check (out/fix1.json, out/imp3.json).

Observations (not filed)

Answer: the combinations do not match Zoho

  1. Zoho checks types when the formula is saved; TAVI accepts every combination. Zoho refused 431 of the pairs TAVI accepts ("Incorrect return type" / "syntax error"):
    • Number functions and operators (Min, Max, Abs, Round, + − * / %, > < >= <=): only number, decimal, currency, percent, long integer.
    • Text functions (Upper, Lower, Trim, Len): only text, email, phone, URL, pick list, multi-select, auto number, user, lookup. Numbers, checkbox and dates must be wrapped in Tostring() first.
    • Date difference (Datecomp): only date and date-time.
    • &&, ||, ! directly on a field: refused for every field type (Zoho wants a true/false expression).
    • == / !=: refused on checkbox, date, date-time.
    • + with text (X + '!'): refused for every type. Zoho does not join text with +; TAVI does (new bug 3).
    • Rich text, File Upload, Image Upload and Multi-Select Lookup cannot be used in any Zoho formula. TAVI accepts them and reads them as empty (NDC-3221).
