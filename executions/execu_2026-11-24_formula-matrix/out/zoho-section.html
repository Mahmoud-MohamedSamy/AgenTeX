Comparison with Zoho CRM (live, 24 Nov 2026)

The same function × field-type pairs were built in Zoho CRM (Enterprise trial org946877290, Leads module) through Zoho's own API, using Zoho's equivalent function where the name differs. Zoho's acceptance was recorded for each formula, and values were read on a filled and an empty lead with the same input values as in TAVI. All Zoho test fields, leads and the account were deleted afterwards (2 hidden helper modules that Zoho creates for File/Image Upload fields cannot be deleted).

Answer: the combinations do not match Zoho

  1. Zoho checks types when the formula is saved; TAVI accepts every combination. Zoho refused 431 of the pairs TAVI accepts ("Incorrect return type" / "syntax error"):
    • Number functions and operators (Min, Max, Abs, Round, + − * / %, > < >= <=): only number, decimal, currency, percent, long integer.
    • Text functions (Upper, Lower, Trim, Len): only text, email, phone, URL, pick list, multi-select, auto number, user, lookup. Numbers, checkbox and dates must be wrapped in Tostring() first.
    • Date difference (Datecomp): only date and date-time.
    • &&, ||, ! directly on a field: refused for every field type (Zoho wants a true/false expression).
    • == / !=: refused on checkbox, date, date-time.
    • + with text (X + '!'): refused for every type. Zoho does not join text with +; TAVI does (new bug 3).
    • Rich text, File Upload, Image Upload and Multi-Select Lookup cannot be used in any Zoho formula. TAVI accepts them and reads them as empty (NDC-3221).
  2. Different function sets. TAVI only: sum, avg, count, coalesce, daysbetween, hoursbetween (Zoho uses Datecomp, in minutes). Zoho only: Ceil, Floor, Sqrt, Naturallog, Base10log, Find, Contains, Startswith, Endswith, Substring, Replace, Now, Newdate, Timepart, Adddate, Subdate, Datecomp, Weekday, Dayofmonth, Hour, Minute, Month, Year, And, Or, Not, CaseInsensitiveEquals (already in the gap ticket NDC-3229).
  3. Where both accept (229 pairs), results differ in these ways (differences caused by the input are left out: Zoho trims spaces when a text field is saved, and the auto-number sequence differs):

Biggest behaviour gap: empty fields. Zoho returns a blank result when an input is empty (abs, round, Tonumber, Len, *, /, comparisons); TAVI returns 0, "" or true/false. Zoho min(empty,100) = 100 (TAVI 0: NDC-3225 confirmed against Zoho). An empty Zoho checkbox counts as false, not blank.
