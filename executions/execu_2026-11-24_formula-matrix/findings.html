New bugs

B1 · Formula field | The + operator joins text instead of adding (Date + 1 gives "2026-11-241")

BugMediumCRM (engine shared with Desk)Differs from Zoho

When the field is not a number, + glues the text and the formula (return type Number) shows it. -, *, / on the same fields give blank. Zoho refuses all of these formulas when saving.

Steps: 1. Add a formula with return type Number: in_pick_list + 1 (or Date, Auto Number, Single Line). 2. Save a record with Pick List = Green, Date = 2026-11-24. 3. Open the record.

Expected (Zoho): the formula is refused at save ("The datatype of param is invalid"), or for dates the days are added. Actual: text is joined.

B2 · Formula field | Formulas treat a User field as empty when it was filled in by its default value

BugMediumCRM onlyInternal inconsistency

The create form pre-fills a User field with the signed-in user, and an API or import create without the field also stores the signed-in user. The record shows that user, but every formula reading the field calculates as if it were empty. Choosing the user by hand works (isblank = false). Desk is not affected: the same Desk record gives isblank = false.

B3 · Modules and Fields | A record cannot be edited when its layout has a Rollup Summary field

BugHighCRM + DeskBlocks users

The Edit form shows the Rollup Summary as an input box and sends its value on Save. The server refuses the whole save, so nothing on the record can be changed from the form. Creating a record works (the empty rollup is not sent).

Steps: 1. Module with a Rollup Summary field on the layout. 2. Open a record → Edit → change any field → Save.

Expected: saved; the rollup is read-only and not sent. Actual: error under the rollup box: "Field 'in_rollup_summary' uses read-only datatype 'rollup_summary' and cannot be set by clients."

CRM record "QA FX matrix - edge values" (QA FX Matrix), Desk record "QA FX matrix - edge values" (QA FX Matrix Desk). No existing Plane ticket found (searched "rollup").
