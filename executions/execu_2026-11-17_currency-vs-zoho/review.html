New bugs

B1 · HIGHState Bug · CRM · Sprint 16 · Global Settings
Currency | A currency added in Settings cannot be used on records
Expected (Zoho, live)A currency added in Setup appears at once in the record Currency field (Deal: EGP, EUR) and records save in it.
Actual (TAVI)EUR active in Settings, but a deal in EUR is refused: "EUR is not one of the allowed values (EGP, USD, AED, JOD, KWD, OMR, SAR)". USD is in that fixed picklist but refused: "USD is not one of the organization's currencies". A record currency must be in both lists, and nothing links them.
Steps and evidence
  1. Settings › Company Settings › Currencies › Add currency: Euro, rate 50, Active.
  2. Create a Deal (Transactions) with Currency = EUR and Amount 1000. Refused.
  3. Create a Deal with Currency = USD (not added in Settings). Refused.
  4. Add USD in Settings, then create the USD deal. It saves with rate 50 and a home value of 50,000.
B2 · MEDIUMState Bug · CRM · Sprint 16 · Global Settings
Currency | Create Deal form has no Currency field and the Amount shows $ instead of the home currency
Expected (Zoho, live)Create Deal shows Currency and a locked Exchange Rate; Amount shows the home code (EGP) until another currency is picked.
Actual (TAVI)The Standard create layout has no Currency or Exchange Rate field, so the user can't choose the record currency. Amount shows "$" while the home currency is EGP. Currency only shows on the record page under Additional Information.
Evidence
B3 · MEDIUMState Bug · CRM · Sprint 16 · Global Settings
Currency | A currency that records use can be deleted
Expected (Zoho, live)"The added currency can only be deactivated and cannot be deleted." Deactivating warns that it can't be chosen for new records; old records keep it.
Actual (TAVI)Delete returns 204 with no warning while a deal is saved in USD. The deal still says USD at rate 50, but USD is gone from the list.
Evidence
B4 · LOWState Bug · CRM · Sprint 16 · Global Settings
Currency | Add currency accepts a code that is not ISO 4217 and silently rounds the exchange rate
Expected (Zoho, live)Currencies come from Zoho's list only. A 12-decimal rate shows "Exchange rate is too large" and Save stays disabled.
Actual (TAVI)Code XYZ is created (201), although the error for bad codes says "must be a 3-letter ISO 4217 code". 0.123456789012 is accepted and stored as 0.123456789 without telling the user. Found through the API; the screen uses a picker.
Evidence

NDC-3101: comment draft

COMMENTExisting bug · stays in Bug

Confirmed on NDC-Staging, 17 Nov. Changing the company currency to AED saves (200, the profile shows AED), but GET /currencies still returns home currency EGP. I reverted it to EGP. Zoho CRM, checked live: the home currency must be confirmed once ("Once you confirm your home currency, you cannot change it later"), and after that, editing the home currency allows only its format, not the currency. Suggest TAVI follows that: lock the company Currency once currencies are set up, instead of letting it differ from the home currency.

Same as Zoho (not filed)

  • Rate 0 or negative refused; Save disabled while the rate is empty.
  • A record stores the rate it was saved with; changing the rate in Settings doesn't change it (TAVI 50 kept after 60; Zoho 0.0175 kept after 0.02).
  • Records show the amount in their currency plus the home value ("$ 1,000.00 ≈ E£ 50,000.00"; Zoho "€ 1.000,00 (EGP 57,142.86)").
  • A deactivated currency can't be chosen for new records; existing records keep it.
  • Home currency can't be added as an extra currency; duplicate codes refused.
  • The exchange rate on a record is filled from Settings.
  • Editing a record whose currency was deleted still works.
