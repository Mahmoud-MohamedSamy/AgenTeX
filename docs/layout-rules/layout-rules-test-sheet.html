What it is, in one line

A layout rule changes a record form while someone fills it in: when a chosen field (the primary field) gets a certain value, other fields or sections appear, become required, or (CRM only) get locked, pre-filled or narrowed.

Layout→Primary field→Condition: "Status is Rejected"→Actions: show "Rejection reason", make it mandatory

Why the business wants it

  • Shorter forms. Agents and sales users only see the fields that matter for this case. A refund ticket shows "Order number"; a general question does not.
  • Complete data at the right moment. A field becomes required only when it makes sense. NDC uses this today: a rejected ticket must have a rejection reason; a closed accounting ticket must have GL, amount and document number.
  • Fewer mistakes. In CRM a rule can lock a field, fill in a value, suggest a value, show a warning message or ask the user to double-check key fields before saving.
  • One form, many cases. Instead of building a separate layout for every situation, one layout adapts.
  • Customers too (Desk). With "Apply to Help Center", the same rule shapes the ticket form customers fill in on the Help Center.

How it works technically

  • A rule belongs to one module and one layout. In Desk it can also be limited to departments.
  • It has a primary field and one or more conditions. Each condition tests the primary field and can add rows on other fields joined with AND / OR.
  • Each condition has actions. "Show" actions mean the target is hidden until a condition shows it. There is no "hide" action.
  • Rules run in the browser, live, as the user changes values on the create, edit and record pages. Several rules on one layout run in the list order.
  • TAVI stores rules at /modules/{id}/layout-rules (list, get, create, update with a version number, delete, reorder) and warns when a field used by a rule is changed (/rule-usage).
  • They are not validation rules (those check values on save and show an error), not map dependency (nested pick lists) and not field permissions. Those are separate features, in Zoho too.

Do Zoho CRM and Zoho Desk use the same layout rules?

Same idea, two separate features. The shape is the same in both: primary field → conditions → actions, up to 25 conditions per rule, 5 rows per condition, 10 rules per layout, and no "hide" action. They differ in what the rules can do and where they run:

What is in TAVI today

  • A "Layout Rules" tab in module settings, in both CRM and Desk, on every module (CRM 15 modules, Desk 10 answered the API on 12 Nov).
  • List with search, filters (layout, status, department), Active switch, delete with confirm, drag to reorder within one layout, and a "Rule not applied" flag.
  • Editor with name, description, layout, primary field, conditions with AND / OR rows (is, is not, is one of, regex, length and more), actions, preview.
  • Desk: departments and "Apply to Help Center". CRM: profiles, messages in English and Arabic.
