TU-06 · TU-12 · TU-18High

Blueprint | A value typed in a transition form skips the field's own checks (text length, pick-list option, contact exists)

Steps

  1. Setup → Automation → Blueprints: create a blueprint with a transition that asks for the field "QA NDC TKT/PNR NO" (single line, max 255) and publish it.
  2. Open a ticket that is in the blueprint and click the transition button.
  3. Paste 400 characters into "QA NDC TKT/PNR NO" and click Run.
  4. Repeat with a transition that asks for Category and send the value "zzz-not-an-option" (through the API — the form only offers real options).
  5. Repeat with a transition that asks for Contact and send a contact id that does not exist (API).

Expected

Each value is refused with the same message a normal ticket edit gives: "QA NDC TKT/PNR NO is too long: … the maximum is 255", "Category: 'zzz-not-an-option' is not one of the allowed values (general, technical, billing, account, feature_request, other)", "Contact: no record exists with id …". The ticket stays in its state.

Actual

All three runs succeed (200), the ticket moves on, and the invalid value is stored: 400 characters in a 255 field, Category = "zzz-not-an-option", Contact = an id of no contact. The same values in a normal edit are refused (TEXT_TOO_LONG, PICKLIST_VALUE_INVALID, LOOKUP_RECORD_NOT_FOUND).

Number, decimal, date, date-time, email and phone fields ARE checked inside the transition. Validation rules are also applied (NDC-3012 still fixed). Related: NDC-3012 (validation rules), NDC-3060 (contact field in the form).

Evidence: results TU-06 / TU-12 / TU-18 in executions/execu_2026-11-24_desk-bp-regression/out/results.jsonl (fresh tickets per run, normal edit compared on the same field).

E2E-01MediumFile

Blueprint | A named transition owner who cannot edit the ticket is told "You are not an owner of this transition"

Steps

  1. Blueprint transition "Approve" with owner = Agent A (Desk Agent profile).
  2. Assign the ticket to Agent B (or to the admin).
  3. Sign in as Agent A and open the ticket.

Expected

Either A can run the step they own, or the message says why not (e.g. "You can't edit this ticket, so you can't run Approve"), and the designer warns that A cannot edit tickets owned by others.

Actual

A is not offered the step; running it returns 403 BLUEPRINT_NOT_OWNER "You are not an owner of this transition" although A is the named owner. Cause: the Desk Agent profile edits only own / unassigned tickets (A's normal edit of the same ticket → 403). On an unassigned ticket A runs it fine.

Same class as NDC-3117 (wrong refusal message). Zoho: transition owners need ticket access too — check whether Zoho shows a clearer reason before filing.
