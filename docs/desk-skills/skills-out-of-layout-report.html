Ticket draft

Title
Desk Tickets: remove "Skills" from the module layout — manage ticket skills only from Settings → Skills and the ticket's Skills tab (like Zoho Desk)

Summary

In TAVI Desk, Skills is a normal field in the Tickets layout. It shows on the New Ticket and Edit Ticket forms and in the layout editor like any other field. In Zoho Desk, skills are not a layout field: Zoho's list of 17 standard ticket fields has no Skills. They are set up on the Setup Skills page (Zoho help: Setup → Customization → Skills) and reach a ticket in three ways: automatically by skill criteria, manually from the Skills section on the ticket page ("Associate Skills"), or by a workflow Add Skills action.

Having Skills in two places is confusing, and the layout field lets users pick skills that don't follow the Skills rules (department, active state, skill type).

Current behaviour (TAVI, NDC-Staging)

  • Tickets → Standard layout → section Ticket Information has the field Skills (skills, multi-select, order 5).
  • It is a plain field: not a system field, can be deleted, moved to other sections or made required.
  • It shows on the New Ticket and Edit Ticket forms, so agents set skills by hand there.
  • The ticket page also has the Skills tab (NDC-2827) with Associate Skills, which checks the ticket's department and active skills.
  • So the same data can be changed from two places with different rules.

Expected behaviour (Zoho Desk)

  1. No Skills field in the layout. Not in the layout editor, New Ticket, Edit Ticket, or the portal / web form.
  2. The Setup Skills page stays the place to manage skills: skill list per department, skill types, criteria, auto-add preferences, Active / Inactive.
  3. The ticket Skills tab stays the place to set skills on one ticket: associate and remove, only active skills of the ticket's department.
  4. Automatic paths keep working: skill criteria on create and update, workflow actions (Add / Remove / Recalculate Ticket Skills, Reassign by Skills), Assign by Skills in the ticket ⋯ menu.
  5. Skills stay visible on the ticket Skills tab. Whether Zoho also offers Skills as a list-view filter is to confirm.
  6. The ticket API still takes skills: Zoho's entitySkills holds up to 10 skill IDs, in order (first = highest priority) for skill-based assignment.

Requested change

  • Remove the skills field from all Tickets layouts (Standard and custom), and stop it being added back from the field list.
  • Keep the stored skills data. Only the layout field goes. Existing tickets keep their skills and show them in the Skills tab.
  • Hide Skills from New Ticket, Edit Ticket, quick create, web forms and the help-center ticket form.
  • Keep skills in the ticket API (like Zoho entitySkills): up to 10 skill IDs, kept in order, with the same rules as the Skills tab. Today's multi-select keeps no order, which is a gap to close with this change.
  • Check other places that read layout fields: list columns and filters, import mapping, export, blueprint and workflow Field update, validation rules, layout rules.

Acceptance criteria

  1. Tickets layout editor (Standard and custom): no Skills field in sections or in the available fields list.
  2. New Ticket, Edit Ticket and quick create: no Skills input.
  3. Web form builder and help-center form: Skills not offered.
  4. Settings → Assignment Rules → Skills: unchanged, everything still works.
  5. Ticket → Skills tab: associate and remove work; only active skills of the ticket's department are offered.
  6. A ticket whose skills were set through the old layout field still shows them in the Skills tab.
  7. Skill criteria, workflow skill actions and Assign by Skills still add skills and assign by them.
  8. Workflow / blueprint Field update and layout rules don't list Skills as a normal field.
  9. Ticket API accepts and returns up to 10 skills per ticket, in order; an 11th is refused.
  10. To confirm vs Zoho: import mapping doesn't offer Skills as a plain field.
  11. To confirm vs Zoho: ticket list view filter by Skills.

Steps to see the current state

  1. Sign in to TAVI Desk (NDC-Staging) as owner.
  2. Setup → Customization → Modules → Tickets → Layouts → Standard.
  3. Section Ticket Information: field Skills is listed (multi-select) and can be moved, made required or deleted.
  4. Open New Ticket: the Skills field is on the form.
  5. Open any ticket → side rail Skills tab: Associate Skills is also there.

Evidence

Standard layout config: apiName: "skills", datatypeKey: "multi_select", isSystemField: false, isDeletable: true, fieldOrder: 5 in section Ticket Information. Source: layout backup saved during retest round 15 (10 Nov 2026).

Zoho references

  • Standard Modules and Fields: 17 ticket fields, no Skills.
  • Assigning Tickets using Workflow and Assignment Rules: Setup → Customization → Skills, auto-add preference, manual or workflow.
  • FAQs: Workflow Rules: Add Skills action.
  • Zoho Desk API, Tickets: entitySkills, max 10, ordered.
  • Ticket Skills panel ("Associate Skills"): checked when NDC-2827 was filed, 9 Nov 2026.
