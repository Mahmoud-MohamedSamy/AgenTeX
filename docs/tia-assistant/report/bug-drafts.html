Bug 1HighDesk + CRMI-12, I-28, I-22, I-24, I-09, I-30, I-10, I-18 (and I-05 unstable)

Tia | Simple questions fail with "Sorry, I couldn't answer that just now" or "would you prefer to speak with one of our team?"

Steps to reproduce

  1. Sign in to Desk as a Desk Agent who has "Chat with Tia".
  2. Open the Ask Tia panel and start a new chat.
  3. Click the suggested question "How many open tickets do I have?".
  4. In a new chat, ask "Count the tickets with status Open that I can see".

Account

Desk Agent (Customer Experience Specialists 2, with "Chat with Tia"); Desk Administrator (QA Team 1); owner

Expected result

Both questions give the number of open tickets the agent can see (40 at the time of the test).

Actual result

The suggested question fails every time (3 of 3, at 14:37, about 15:20 and about 15:40 UTC) with: "I can't confirm that from our systems right now, and I don't want to guess. Would you like me to try again, or would you prefer to speak with one of our team?". The reworded question returns 40, which is correct. The second sentence is wording for customers and does not belong in a staff assistant.

  • Same result in Arabic: "كم عدد التذاكر المفتوحة لدي؟" gets the Arabic version of the same reply (I-28).
  • "How many chats are waiting right now?" (Desk admin), twice: the customer-bot reply (I-22).
  • "Show my QA TIA deal" (CRM), twice: "Sorry, I couldn't answer that just now. Please try rephrasing your question." 3 such deals exist (I-24).
  • Leads, contacts and deals counted in one question, twice: the same "Sorry…" reply (I-09).
  • "What did the customer say in ticket QA TIA T3 last week?", twice: the same "Sorry…" reply; expected "there is no such message" (I-30).
  • Run a saved report by name: "invalid reporting definition", or the customer-bot reply (I-10).
  • Ask about a blueprint: "Sorry…", or "I need the specific module name or key…" on a Desk ticket blueprint (I-18).

Bug 3HighDeskJ-06, E2E-1, E2E-3 (blocks O-03)

Tia | A private ticket comment can never be proposed, although Tia offers "Draft a private comment" on ticket pages

Steps to reproduce

  1. As an admin, open Settings → Integrations → Tia → Edit → Tools. Look at the list of modules Tia may change.
  2. Sign in to Desk as a Desk Agent with "Chat with Tia" and open a ticket in your department (QA TIA T1).
  3. Open Ask Tia. Click the suggestion "Draft a private comment", or ask "Add a private comment to this ticket: checked by QA".

Account

Desk Agent (CES 2), who has the "add ticket comment" permission (desk:ticket:comment)

Expected result

Tia shows an action card with the private comment. On Confirm, the comment is added to the ticket.

Actual result

Tia answers: "I cannot add a private comment… because your workspace admin has not allowed me to make changes to Desk tickets." The module picker (GET /agents/modules) lists only 15 CRM modules, so an admin has no way to allow Desk tickets. The feature Tia suggests on every ticket page cannot work, and "What Tia can see" still lists "Propose a ticket comment".

  • The agent has desk:ticket:comment, so it is not a permission problem on the user's side.
  • This stops the Desk journeys E2E-1 and E2E-3 at the comment step.

Bug 6MediumDesk + CRME-08, E-12, J-08, J-10 (blocks O-07)

Tia | "Propose a setup change" only supports 4 fixed recipes; tags and blueprints cannot be proposed

Steps to reproduce

  1. Open Settings → Integrations → Tia → Edit → Setup areas. Set "Ticket tags" and "Blueprints" to Propose. Deploy.
  2. In Desk, ask Tia "Create a new ticket tag named QA TIA Tag".
  3. In CRM, ask Tia to propose a blueprint for Deals (3 tries, as the owner and the CRM admin).

Account

Owner; CRM Admin (Mahmoud Mohamed)

Expected result

Each request gives a "Setup change" card the admin can confirm, for any area set to Propose.

Actual result

The tag request asks for a department, then refuses: "tag name must be one of the predefined values: assignment_by_lead_source, approval_above_amount, task_on_lead_created, or sla_by_priority". The blueprint request never gives a card (3 tries): "…not among the allowed recipe names for the tia_proposeSetupChange tool…" or "the blueprint tool requires specific valid inputs".

  • The setup page offers Propose for 182 setup areas, but only these 4 recipes can be proposed.
  • The refusals show internal tool and recipe names (see bug 2).
  • For workflow rules (one of the 4 recipes), the requested rule name is replaced and the card shows raw JSON (finding E-07).

Tia | Tia setup changes are not written to the audit log

Steps to reproduce

  1. Open Settings → Integrations → Tia. Edit the description and save. Deploy.
  2. Deactivate Tia, then activate it. Turn the AI "Tia" switch off and on, and change the daily credit cap.
  3. Read the audit log (GET /audit/events, latest 100, also filtered to app_key=agents) and look for these changes.

Account

Owner

Expected result

Each save, deploy, deactivate, delete, restore and AI policy change is in the audit log, with the user and the time.

Actual result

None of them is there. Between 14:15 and 14:48 UTC the owner made 9 draft saves, 7 deploys, a deactivate, a delete and a restore. The only agent entry is "agent_principal created Tia" by ai-agents at 14:48:22 (from the restore). AI policy changes (Tia switch and caps) are missing too.

  • Records that Tia creates through action cards are logged correctly, with channel "tia".
