What matters for go-live

  • Access is safe. No user could see another user's chats, or data from a module, layout or record they have no access to, through Tia.
  • Saving the strong-step limits on the Tia setup page wipes other runtime settings (takeover off, session turn cap 30 → 1). Filed High as NDC-3345.
  • Answers with a date, stage name, status or sum are mostly wrong ("no leads created last month" when there are 1,153). Filed High as NDC-3359.
  • Only 21.6% of Tia's tool calls succeed in Observability (NDC-3357); internal error text still reaches users (NDC-3346).
  • Custom actions do not work in practice through Tia (NDC-3355, NDC-3356). Owner changes by user name fail (NDC-3353).

Bugs NDC-3359…3362 in full

NDC-3359HighCRM

Tia | Questions with a date, a stage name or a status give wrong answers ("no leads created last month" when there are 1,153), and amounts cannot be summed

Plain counts are right, but as soon as a question has a date range, a picklist label or a status condition, Tia answers "none" or fails. Tia also cannot add up an amount field.

Steps to reproduce
  1. Sign in to CRM as the Owner and open Tia.
  2. Ask each question in a new chat: How many leads were created last month? / How many leads were created this month? / How many leads were created today? / How many leads were created in October 2026? / How many deals are in the Closed Won stage? / How many tasks are not completed yet? / What is the total amount of all deals?
  3. Compare with the Leads, Deals and Tasks lists filtered the same way.
Expected result

Tia gives the same numbers as the filtered lists: last month (October) 1,153; this month 2; today 1; Closed Won 3; tasks not completed 121; total deal amount 5,533,912,086,090.

Actual result

Last month, this month, this week and today: "No leads were created … based on the records you can access" (today also once "Sorry, I couldn't answer that just now"). October 2026: "The app is currently not responding". Closed Won: "There are currently no deals in the Closed Won stage". Tasks not completed: "Sorry, I couldn't answer that just now. Please try rephrasing your question." Total amount: "I do not have the total amount of all deals available from the data."

Notes
  • "How many deals are in the stage closed_won?" (the internal value) gives the right answer, 3, so the stage label is not matched to its value.
  • Each question was asked twice with the same result.
  • Right in the same run: leads created last week (0), tasks I own (0), the largest deal (AP-75), and plain module counts (25 of 27 right in an earlier run).
NDC-3360MediumCRM

Tia | Screen readers do not announce Tia's answers, and messages are not marked as yours or Tia's

The Tia panel has no live region and the chat is not marked up as a list of messages, so a screen reader user does not hear when Tia answers and cannot tell who said what.

Steps to reproduce
  1. Open Tia with a screen reader running (or inspect the panel's accessibility tree).
  2. Send: How many deals are there?
  3. Then send a request that returns a card, for example: Create a lead with first name "QA" and last name "Reader". Prepare the card for me to confirm.
Expected result

"Thinking…" and each new answer are announced (polite live region). Each message is announced as from you or from Tia, inside a message list (role log or list). Card content is separate from the next message.

Actual result

No element in the panel has aria-live or role status/log; the "Thinking…" indicator has no role. In the accessibility tree the user's question is plain text and Tia's answer a paragraph, with no speaker. The count card and the next question are read as one line: "Count 73 Total: 73 Create a lead with first name …".

Notes
  • Checked through the browser accessibility tree in Edge (what NVDA/JAWS read); no screen reader is installed on the test machine.
  • Fine: the panel is a dialog named "Tia", all buttons have names, focus goes to the message box when the panel opens and stays there after an answer.
NDC-3361LowCRM

Tia | In Firefox, the Tab key gets stuck on the Send button

With the keyboard, Firefox users cannot move past the Send button in the Tia panel.

Steps to reproduce
  1. Open CRM in Firefox and open Tia.
  2. Click in the message box and type a few letters.
  3. Press Tab several times.
Expected result

Focus moves from the message box to Send and on to the next control (in Edge it moves on).

Actual result

Focus moves to Send and stays there on every further Tab. Shift+Tab moves back normally.

Notes
  • Edge and WebKit move past Send (there focus then leaves the panel, see NDC-3260).

NDC-3366LowCRM / Omnichannel

Tia | After rolling back to an older version, the draft keeps the newer settings, so the next Deploy brings them back

Steps

Deploy a change (for example a per-user daily limit of 1), then redeploy the previous version from the version history. Open the Tia setup page.

Expected result

Either the draft is reset to the version that is now live, or the page clearly warns that the draft still holds the rolled-back change.

Actual result

The live version is the old one (the change is gone for users), but the draft still has the daily limit of 1 and shows undeployed changes. The next Deploy would bring the rolled-back change back without warning.
