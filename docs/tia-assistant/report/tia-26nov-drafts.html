P7-1LowCRM · Bug · Sprint 17 · AI Features

Tia | An expired card disappears from the chat without saying it expired

A card that is not answered within 15 minutes expires. When the user opens that chat again, the card is gone with no explanation, while Tia's text above it still asks the user to confirm.

Steps to reproduce
  1. Sign in to CRM as the Owner and open Tia.
  2. Send: Create a lead with first name "QA TIA EXP card" and last name "Expired". Prepare the card for me to confirm.
  3. Do not press Confirm or Cancel. Wait 15 minutes.
  4. Open the chat again from Past chats.
Expected result

The card is still shown, marked as expired, with no Confirm button and a short note such as "This request has expired. Ask Tia again."

Actual result

The card is gone. The chat still shows Tia's text "I have prepared the lead card… If you confirm, the lead will be created in the system.", with nothing to confirm and no note that it expired.

Notes
  • A card that has not expired does show Confirm and Cancel when the chat is reopened from Past chats.
  • Confirming the expired card through the API is refused correctly: 409 TIA_ACTION_EXPIRED. No lead was created.
  • Evidence: screenshots EXP-before.png / EXP-after.png and FRESH-before.png / FRESH-after.png in the run folder.
Environment

NDC-Staging (staging-crm.taviportal.com), Tia v27 (baseline settings), Edge and the Tia API, 26 Nov 2026, Owner account. Test data deleted afterwards.

P7-2LowCRM · Bug · Sprint 17 · AI Features

Tia | Knowledge base: an unsupported file type is accepted and only fails later, and deleted files stay listed in Tia's settings

Tia's knowledge base supports PDF, Markdown and text files. The upload screen blocks other types, but the server accepts them and fails later. Deleting a document also leaves it listed in Tia's settings.

Steps to reproduce
  1. Upload a CSV file and register it as a Tia knowledge-base document (POST /agents/kb/documents with its file_id).
  2. Check the document status in the knowledge-base list.
  3. Register a supported file (for example a .txt), add it to Tia's knowledge base and deploy.
  4. Delete that document (DELETE /agents/kb/documents/{id}) and read Tia's settings.
Expected result

The CSV is refused when it is registered, with a message that only PDF, Markdown and text are supported. Deleting a document also removes it from Tia's knowledge-base list.

Actual result

The CSV is accepted (200) and later shows status "failed". After the document is deleted, its id is still in Tia's kb_document_ids.

Notes
  • Tia stops using a deleted file at once, so the effect is on the settings only.
  • Working as expected: TXT, Markdown and PDF were processed and answered 3 of 3; a 21 MB file is refused with "Knowledge-base documents are capped at 20MB."
Environment

NDC-Staging (staging-crm.taviportal.com), Tia v27 (baseline settings), Edge and the Tia API, 26 Nov 2026, Owner account. Test data deleted afterwards.
