Rebuild of NDC's setup on TAVI (3 Nov 2026)

We rebuilt NDC's core Zoho Desk setup on NDC-Staging. Every object starts with "QA NDC" and is kept as the NDC reference setup:

  • 8 core departments: Manual Invoice, NDC Finance, Financial approval, Accounting, Quality Assurance, Client Complaints, Clients' Financial Investigations, FLY-WT Refund.
  • Plus the 23 branch departments their workflows share tickets into.
  • 32 teams, 41 statuses, 94 custom fields, 10 layouts, 7 layout rules, 1 validation rule, 6 blueprints (81 transitions), 42 of 80 workflows, 9 SLA policies, 240 notification settings.
  • Then smoke-tested with tickets.

Works like NDC: custom statuses with types; large pick lists (up to 188 values); decimal, currency and date fields; a layout assigned to a department; layout rules (show fields or sections, require fields, checked on save); the "Reject needs a reason" validation rule; blueprints with team and ticket-owner transitions, required fields and after-actions; the share-ticket workflow (a QA ticket shared to its branch); SLA policies with NDC's targets and escalations; per-department notification rules.

Missing: Workflow rules

M-18

Workflow rule limit

P0
NDC's Zoho92 workflow rules, 90 active; all but 2 were changed in 2024–2026. 80 active rules are in the 8 core departments alone.
TAVI nowStops at 50 rules per module for the whole tenant. The 51st is refused ("Module has reached the limit of 50 rules"), and the Workflow Rules page doesn't show the limit or how many are used. 38 of NDC's core rules could not be created.
Expected: the Workflow Rules page shows the limit and how many rules are used, and the limit can be set per tenant (at least NDC's 92).
M-20

Clear the ticket owner from a workflow

High
NDC's ZohoNDC Finance's rules "Ticket owner -1", "Ticket owner -2", "R1" and "R2" use a Field Update that sets Team = a team (e.g. Top-up Managers) and Ticket Owner = Unassigned. The ticket goes back to the team queue for any member to pick up.
TAVI nowThe workflow Field Update refuses the owner field, and no other action clears it. The ticket stays with the previous agent.
Expected: a workflow can set Ticket Owner to Unassigned, alone or together with a team.
A-3

Trigger "on create, or when these fields change"

High
NDC's ZohoA rule can run when the ticket is created, and later only when chosen fields change. For example, QA "GDS B2B" runs on create and when Related Branch or Status changes. 38 of NDC's core rules use this.
TAVI nowThe triggers are on create, on any edit, on create or any edit, and when fields change (edits only). "When fields change" misses the creation (Manual Invoice "Close Ticket" didn't fire on a new ticket), and "create or any edit" fires on every edit.
Expected: an "also run on create" option on the field-change trigger.
A-2

Assign to a team and an agent in one rule

High
NDC's ZohoThe action "Assign Ticket → Team with Agent" puts the ticket in a team and gives it to an agent of that team in one step. 19 NDC rules use it, e.g. Accounting "ADM Assignment Airline Ops".
TAVI nowOnly one assignment action per rule ("A rule can have only one OwnerAssignment action"), so a rule sets the team or the agent, not both.
Expected: one rule can set both the team and the agent.
A-1

Same rule name in different departments

Low
NDC's ZohoRule names such as "GDS B2B", "GDS B2C", "Airline Ops", "LCC" and "KSA" are reused in up to 4 departments. Names only need to be unique within a department.
TAVI nowNames must be unique per module ("A rule named … already exists"). Renaming works around it.
Expected: rule names only need to be unique within a department.

Missing: Layouts and statuses

M-17

More than one layout per department

High
NDC's ZohoA department can have several ticket forms, and the agent picks one when creating a ticket. Accounting has "Accounting" (18 fields, normal requests) and "ADM" (42 fields, ADM disputes). NDC Finance has "NDC Finance" (17 fields) and "NDC Finance TKT" (31 fields, top-up requests).
TAVI nowOne layout per department. A second one is refused ("A department can use only one layout of a module"), so the ADM and top-up forms can't be used by their departments.
Expected (as in NDC's Zoho): a department can have several layouts. When creating a ticket in that department, the agent picks the layout, with the department's default already selected. The ticket keeps the chosen layout with its fields, mandatory fields and layout rules, and the layout can be changed on the ticket later.
A-9

Ticket statuses per department

HighReworded 3 Nov
NDC's ZohoSetup → Ticket Status is chosen by department first, then by that department's layout (e.g. Accounting → Accounting / ADM). Each department, and each of its forms, has its own list:
  • Manual Invoice 8; FLY-WT Refund 8
  • Accounting → ADM 10: Open, On Hold, Escalated, Closed, System Admin, Dep Manager, Finance team after Validation, Distributor, Governance, HR Escalation
  • NDC Finance → NDC Finance TKT 6
  • Financial approval 13; Clients' Financial Investigations 13
  • Client Complaints, Accounting (Accounting form) and NDC Finance: only Open / On Hold / Escalated / Closed
Each status also has a fall-back-to-default setting.
TAVI nowOne tenant-wide list of 41 statuses for every department. Setup has no department or layout picker for statuses. A per-layout list can be saved on the layout through the API, but a ticket with a status outside it is still accepted.
Expected (as in NDC's Zoho): statuses are set per department, and per layout within it. A ticket is only offered, and only accepts, its department's or layout's statuses.

Missing: Notifications

M-21

Team notification when a comment is edited

Low
NDC's ZohoThe Quality Assurance department has "Team Notification → Editing a comment" switched on.
TAVI nowTeam notifications exist for assigning, replies, adding a comment and mentions, but not for an edited comment.
Expected: a team notification rule for an edited comment.
