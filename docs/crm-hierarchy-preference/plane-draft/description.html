Summary

We compared CRM's Hierarchy Preference (Company Settings, Role-based / Reporting-based) with Zoho CRM. This ticket lists what Zoho has and CRM does not have yet. There is no PRD for this feature in Plane, so items are not mapped to phases.

Already done in CRM

  • Hierarchy Preference tab with Role-based and Reporting-based modes and a confirm dialog.

  • The setting is versioned; a second admin saving at the same time gets "Hierarchy preference was changed elsewhere".

  • Role-based follows profile rank (CRM Admin 700, Manager 500, Supervisor 300, User 100).

  • Reporting manager can be set by an admin in the Users window; loops are rejected.

  • Users can see their direct reports on Personal Settings → Reporting Hierarchy (Reporting mode only).

  • Record visibility per module: Public or Hierarchy.

  • Approvals can go to the "Manager" or the "submitter's manager"; assignment rules can use "Reporting Manager".

  • CRM also has Change history and a Live preview on the tab, which Zoho does not have.

Missing — settings page

  1. Choice of who manages the records of users with no manager ("Any user higher up in the hierarchy" or "Super admin and Administrators"). Reporting mode only.
  2. Warning when switching back to Role that lists where "Reporting To" is used (reports, criteria, filters, merge fields), with keep or remove for each. Today the same generic dialog shows both ways.

Missing — role hierarchy

  1. Roles tree separate from profiles. Today Role-based uses profile rank, so a permission profile also decides who sees what.
  2. A superior sees only their own branch. Today the preview says "a Manager sees every User in the tenant" and the visibility hint says "lower-ranked users in their department".
  3. Share Data with Peers per role.
  4. Move users and sub-roles to another role before deleting a role ("Transfer & Delete").

Missing — reporting hierarchy

  1. Only users in a higher role can be chosen as manager. Today every user except self is offered.
  2. User picker for the manager on the Personal Settings page. Today it is a free-text "Paste a user ID" field.
  3. Reporting Hierarchy section on the user's details (manager and direct reports), and a Reports To column and filter on the Users list.
  4. When a manager is deleted or deactivated, ask where to move their reports.
  5. When a manager's role changes and breaks the chain, ask to change the reporting manager.

Missing — where the hierarchy is used

  1. "Reporting To" in reports, custom view criteria, list filters and merge fields. Today only assignment-rule criteria have it.
  2. Workflow email alert to the record owner's manager or subordinates.
  3. "Reporting Manager" as a blueprint transition owner.
  4. Approval levels up the hierarchy (1st, 2nd, 3rd level, or all up to level 2 or 3), and a fallback when the owner has no manager.

Missing — data sharing

  1. Default access options per module: Private, Public Read Only, Public Read/Write, Public Read/Write/Delete. Today CRM has Public or Hierarchy only.
  2. Sharing rules (owner-based or criteria-based, from / to role, role and subordinates, group, "Superiors Allowed"). /iam/sharing-rules and /settings/data-sharing return 404.

Missing — API

  1. Roles API (list, create, update, delete with transfer). Today /iam/roles and /iam/hierarchy return 404; only profiles are served.
  2. Read any user's subordinates. Today only /iam/me/subordinates exists; /iam/users/{id}/subordinates returns 404.

Could not be checked

  • Whether switching the mode changes what users see. This needs a mode switch and a second signed-in user; it is covered in the test run. Please confirm a Supervisor-rank test account so we can test what a superior sees.

  • Zoho's Reporting-mode screens (items 1, 2, 7, 9) are based on Zoho's help pages. Please approve switching the Zoho reference org to Reporting Hierarchy and back so we can capture them.

  • Items 6, 10, 11 and 15 need write actions on QA data. They are covered in the test run.

Additional notes

  • Not gaps: forecast hierarchy and territories (CRM has no Forecasts or Territories module).

  • Possible bug to check separately: the Live preview text and the Hierarchy visibility hint describe Role mode differently.

  • Possible bug to check separately: any user can set their own manager by pasting any user ID on the Personal page.

  • Possible bug to check separately: the Reporting manager field works in Role mode, but the Personal page disappears.

  • Possible bug to check separately: Change history does not show who made the change, though the API has it.

  • Test run 21 Oct 2026 found that switching the mode changes nothing users can see (superiors and reporting managers get 403 on their team's leads). These are bugs, to be filed separately: executions/execu_2026-10-21_crm-hierarchy-preference/report.md.
