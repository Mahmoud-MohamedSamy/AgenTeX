Zoho Survey, explained for the build team

Zoho Survey is Zoho's standalone survey and feedback app. You build a questionnaire, publish it through one or more channels, collect answers and analyse them. This page explains how it is organised and what each part does, in enough detail to plan and build an equivalent module for TAVI.

1. What Zoho Survey is

It is a separate Zoho product, not a module inside CRM or Desk. It has its own portal, users and billing. It connects to CRM, Desk and other apps through integrations. The work splits into five stages, and the app's tabs follow them:

StageWhere in the appWhat happens
BuildBuilder › EditorPages, questions, choices, logic
ConfigureBuilder › Settings, ThemesIntro and end pages, variables, timer, quotas, look, languages
ConnectBuilder › HubIntegrations (CRM, Desk, Sheets…), trigger emails, webhooks, functions
PublishBuilder › PublishCollectors: links, email, SMS, embed, pop-up, QR, offline; restrictions
AnalyseSummary (left rail) › Reports, ResponsesSummary charts, individual responses, filters, cross-tab, trend, dashboards, exports

When a survey is open, the left rail shows Summary, Builder and Audit Logs. The top tabs are Editor · Settings · Themes · Hub · Publish, with Advanced Options and Preview on the right. SEEN LIVE

  • Portal: the organisation. It holds users, custom domains, sender addresses, connected apps and hash keys. One login can own several portals ("My Portals"). DOCS
  • Department: a workspace inside the portal. Users get a role per department. Enterprise only. Our trial portal has one, "My Department", picked from a dropdown in the header. SEEN LIVE
  • Survey: name, category and tags (there are no folders; tags do that job). The URL pattern is #/portal/{portalId}/department/{deptId}/survey/{surveyId}/buildersurvey. SEEN LIVE
  • Page: title (max 100 chars) and description (max 5,000 chars). No page limit. SEEN LIVE
  • Question: internal IDs are letters (A, B, C…), used by scripts and piping. DOCS
  • Collector: one distribution channel with its own link, settings and response stream. A survey can have many. Responses always record which collector they came through. DOCS

6. Settings every question shares

Editor tab SEEN LIVE

  • Rich-text question (bold, italic, underline, size, colours, link, image, video, lists, alignment); 65,535 character counter
  • Insert Variable: pipe earlier answers or variables into the text
  • Choices typed one per line, or as Individual Textboxes, or from Predefined Choices (ready lists)
  • Carry forward choices from previous questions
  • Add "Other" field
  • Advanced options: choice display format, choice order (randomise / flip / rotate / sort, keep last N fixed), prepopulate answer, "Comments" field, question hint

Validation tab SEEN LIVE

  • Mark as Mandatory, with its own error message
  • Validate Answers: per type (required count, length, number range, regex…)
  • Validate with Javascript Snippet: custom script rule

Display Logic tab SEEN LIVE

  • Default "Always display this question"
  • Other modes: never display, display only if, hide only if (conditions)
  • A hidden mandatory question is not required

Answer Display Logic tab SEEN LIVE

  • Show or hide single choices based on conditions
  • If too few choices remain, the whole question hides

Also available: a "Not applicable" option on rating types (left out of averages), Encrypt answer and Mark as health information (ePHI) on text and date types, and exclusive choices on multi-answer types. DOCS

7. Logic and branching

Page Skip Logic SEEN LIVE

Set per page from the page header › Logic › Page Skip Logic. A test rule was built and saved: If "How likely are you to recommend us?" is less than 7, skip to Survey End Page.

  • Conditions are rows numbered C1, C2…: If [subject] [operator] [operand] skip to [target]. + Add Condition adds more rows.
  • Subject: any question on the page, or a Custom Script › Javascript Snippet (locked behind a plan).
  • Operators for a numeric/NPS question: Equal to, Not equal to, Less than, Greater than, In Between, Answered, Not answered. The operand for NPS is a 0–10 picker.
  • Targets: Go to next page (Default), Survey End Page, Disqualification Page, or any later page ("Page 2 : Details").
  • Default Flow ("After this page, go to …") applies when no condition matches.
  • Confirmation toast: "The logic has been saved".

Other logic DOCS

  • Question display logic and answer display logic (above). Several conditions join with And/Or. With more than two, an editable condition pattern such as (C1 and C2) or C3 appears.
  • Text operators: Equal to, Not equal to, Contains, Doesn't contain, Starts with, Ends with, Answered, Not answered.
  • Condition subjects can also be variables (URL parameters, CRM, HubSpot), scores, or a collector.
  • Disqualification: sends the respondent to the Disqualification page. The response is stored with status Disqualified.
  • Question Randomization (page Logic menu): same order, all questions, or selected questions. Questions linked by logic or piping on the same page are left out.
  • End Page Logic: a different end page per condition.
  • Custom script (JavaScript or Deluge): reads application.survey.question.A.response and application.survey.urlparam["x"] and returns true or false. It runs in a sandbox that blocks window, document and eval.

Scoring and quizzes DOCS

  • Two methods: Correct Answer Scoring (quiz, with a grading scale such as Pass/Fail or A/B/C) and Weighted Scoring (a value per choice, summed). Negative values are allowed.
  • Score values (total, %, per page) can be shown on the end page, used in logic and sent in trigger emails.
  • Not scorable: ranking, email, contact, name, file upload, heading.

8. Variables, piping and prefill

  • Custom variables (Settings › Variables › Create Variable, "Capture and store values from URLs or external sources"): URL parameter name, label shown in reports, type Text / Email / Number / Choice / Date, optional encryption. Example link: …/survey?email=a@b.com&region=cairo. SEEN LIVE (screen) DOCS (fields)
  • Respondent variables come in automatically from email or SMS invites, CRM, Desk, unique-URL CSVs and so on (email, first name, last name, phone, up to six extra variables).
  • Piping: Insert Variable in a question, page title or end page puts in an earlier answer or variable. If the value is empty, the question is hidden.
  • Prefill (prepopulate): from an initial value or a source (URL parameter, CRM record, HubSpot). It can be locked or left editable. An option skips page 1 if every question on it is prefilled.
  • Carry forward: reuse the choices of an earlier question. Take all of them, or only those displayed, not displayed, answered or not answered.

10. Themes, branding and languages

  • Themes: ready themes plus "My Themes". The editor has General (colours, font, corners, shadow, border, form size), Background (image or pattern), Header (logo, title, alignment), Body (question and answer fonts, answer field colours, buttons) and Footer tabs. No custom CSS was found. DOCS
  • White label: your own subdomain (CNAME, SSL provided by Zoho), custom favicon, removal of Zoho branding. Paid plans only. DOCS
  • Languages: one default and any number of extra languages (Zoho says 135, with 91 having built-in system messages). Each response stores its language, and reports can filter by it. RTL is supported (Arabic, Hebrew, Urdu, Persian). This matters for TAVI's Arabic users. DOCS
  • Accessibility: an "Advanced Accessibility" switch, tested with screen readers. DOCS

11. Publishing: collectors

Publishing means adding at least one collector. Each collector is one channel with its own link, its own restrictions and its own response count, so you can compare channels in reports. DOCS

Public access

  • Public link: copy URL, short link, share to Facebook / X / LinkedIn / WhatsApp / Telegram
  • Website embed: iframe; posts surveySize and completion events to the parent page
  • Pop-up: show on all or chosen pages; trigger on load, after N seconds, on exit intent, after N% scroll, or from a script call; position, height, minimise, "do not show again"
  • QR code: copy or download
  • Offline / kiosk: mobile app or browser; admin password, auto-restart, auto-upload when back online
  • Buy responses: paid panel targeted by country, age, gender and so on

Private audience

  • Email invites: template (logo, colours, variables, "Begin Survey" button or the first question inside the email), sender name and address, recipients from CSV / XLS / manual or trigger, send now / scheduled / recurring
  • Reminders to people who did not answer or only partly answered
  • Tracking: sent, opened, unopened, responded, partial, bounced, unsubscribed, failed
  • Unique URLs: upload a CSV and get one personal link per row back
  • SMS invites: Zoho SMS, Twilio, Clickatell, SMS Magic
  • Other services: links for Mailchimp, HubSpot and similar, with identity parameters and an optional HMAC hash against tampering
  • Zoho services: CRM, Desk, Campaigns contact lists

Organisation

  • Invite members of the organisation; they answer while signed in (Zoho account or SAML)

Per collector you can rename it, stop collecting responses, edit it or delete it. An invitation API exists: POST …/collectors/{id}/distributions/{id}/email/sendinvitation with a contactsList array (60 calls per minute). DOCS

  • Each Next saves the page. A respondent who stops after page 1 leaves a Partial response. Submitting the last page makes it Completed.
  • Required questions are checked page by page, with the question's own error message.
  • Display logic is re-checked on every change, so questions appear and disappear live.
  • Save and Continue Later emails a resume link (from page 2 onward).
  • End page options: thank you, summary, submitted answers, custom message or redirect. Scores and variables can be shown.
  • Preview mode lets authors test. Preview answers are not saved as responses.

Formulas the build needs

  • NPS = % promoters (9–10) − % detractors (0–6), range −100 to +100.
  • CSAT = positive answers ÷ answered × 100. "Positive" depends on scale size: 5-point → 4–5, 10-point → 6–10, NPS → 9–10 (Zoho publishes the full table: 3→3, 4→3–4, 6→4–6, 7→5–7, 8→5–8, 9→5–9, 11→6–11).
  • Average rating excludes "Not applicable" answers.
  • Sentiment (English, long answers): Anger, Disappointment, Neutral, Sarcasm, Happy, Extremely Happy.

16. Hub: integrations and triggers

The Hub tab holds what happens after a response arrives. DOCS

Triggers (run on submit)

  • Trigger email: from a verified sender; to fixed addresses or an email answer; subject and body with variables and scores; attach the response PDF; send only if conditions match
  • Trigger SMS
  • Webhook: POST to a URL as form data or JSON; you choose the key/value pairs (answers, variables, fixed values); query parameters and headers
  • Function: server script (Deluge) with connections to other apps

Zoho CRM

  • Map questions to fields of any module (Leads, Contacts, Deals, Cases, custom…)
  • Action: Add record, Update record (by record ID in the link) or Add/Update (match on the duplicate-check field)
  • Attach the response PDF and uploaded files
  • CRM side: "Zoho Survey" related list with Send Survey, sent-by, source, View Response / "Yet to respond", Take Survey

Zoho Desk

  • Create a ticket from each response (department, layout, field mapping)
  • Desk side: map up to 20 surveys per department; agents insert a survey link in a reply or "Send and Close"; the link carries the requester email, ticket ID and agent name
  • Reports per agent and per contact, plus a tab on the ticket

Others

  • Google Sheets, Salesforce, Slack, Microsoft Teams, Zapier, Zoho Flow, Zoho Analytics, Power BI, HubSpot, Mailchimp, Shopify, Zendesk
  • Every integration has a sync-status list (successful, untried, failed) with retry
  • Responses received before the integration was set up need a manual sync

Two design rules matter early. First, once a survey has responses, editing it must not break old answers: keep question and choice IDs stable and block type changes after publish, as Zoho does. Second, store answers per question (not as one big JSON) so filters, cross-tabs and trends can query them.

20. Suggested build phases

  1. Core builder and runtime: survey list (draft/published/closed/trash, tags, search), pages, the most-used question types (choice, dropdown, rating, star, NPS, matrix choice, text, number, email, date, heading), required + validation, public link collector, respondent page with partial save, thank-you page, response list and individual view, summary report, CSV/XLSX export.
  2. Logic and settings: display logic, page skip logic, disqualification, piping, URL variables, prefill, intro / T&C / end pages, close / reopen, end date, response limit, one-per rules, password, themes and logo, Arabic (RTL) and multiple languages.
  3. Distribution: email invites with tracking and reminders, unique links, embed, pop-up, QR, several collectors per survey, quotas.
  4. Analytics: filters, cross-tab, trend, NPS/CSAT metrics, dashboards, shared reports, scheduled reports, PDF export, notes and tags.
