Summary

We compared CRM's Global Sets with Zoho CRM. This ticket lists what Zoho has and CRM does not have yet. The feature spec is NDC-2806. Each item says where it sits in NDC-2806 (S1–S8 are its scope items).

Already done in CRM

  • Global Sets tab under Modules and Fields: list, search, create, edit, clone (X_Cloned, X_Cloned_2) and delete.

  • Editor: name, description, colours, bulk add, drag to reorder, Sort A–Z, remove to Unused and move back (50 at a time).

  • Convert a field's own pick list into a global set, and link an existing pick list with the mapping popup (records per value, Map to, Move to unused, View associated places).

  • Used In per field: layouts, custom views, workflow rules, saved actions, approval and review processes, custom actions.

  • Safeguards: more than 15 linked fields blocks delete and replace; locked fields (Approval Status, status fields) cannot use a set; duplicate names and values are refused; a stale save is refused.

  • Permissions crm:global_set:view and crm:global_set:manage, plus audit entries.

  • CRM also lets multi-select and radio-button fields use a set, which Zoho does not allow.

Missing — managing values

  1. Replace that updates every place using the value. Today CRM refuses for views (NDC-2867) and skips workflows (NDC-2866). Zoho changes records, view and workflow criteria, field updates and field dependency, and moves the old value to Unused. NDC-2806 S3.
  2. Delete an unused value for good. Today a value can only go to Unused and back. Zoho deletes one value at a time from Unused and refuses values still in use.
  3. Saved sort order (Entered / Alphabetical) that list views, reports and dashboards follow. Today there is only a one-time Sort A–Z button. Not in NDC-2806.
  4. Add Predefined Choices in the values menu. Not in NDC-2806.

Missing — sets Zoho ships

  1. Ready-made Source and Industry sets. Today Lead Source and Industry are separate pick lists per module. Not in NDC-2806.
  2. Countries and States list behind every address Country/State field, with codes and a Configure page. Today country fields are free text. Not in NDC-2806.

Missing — where admins see a set is used

  1. Used In listing reports, field dependencies and blueprints. Today it says "Reports … are not listed here yet". NDC-2806 S6.
  2. Which value is used where (per value, e.g. which field update or workflow uses "Gold"). Today Used In is per field only.
  3. Created By column, and Used In showing module names as links. Today the list shows a field count and last modified only.

Missing — limits and API

  1. Limits per tenant: Zoho allows 30 sets (Enterprise), 15 linked pick lists per module, 30 fields per set, 500 unused values. CRM only has 1000 values and the 15-field rule; we created 51 sets without a limit.
  2. Replaced values history and a "done" notification for long replaces.

Could not be checked

  • Field dependency with a global-set field. A new field cannot be created from a set today (NDC-2865), and we did not change shared layouts to build dependency rules. Please fix NDC-2865 first so we can test field dependency with a set field.

Additional notes

  • Not gaps: Zoho runs Replace in the background; Zoho Sandbox rules; Zoho's API accepting values that are not in the set (CRM should not copy this).

  • Bugs found while testing, filed separately: NDC-2865 (new field from a set cannot be saved), NDC-2866 (Replace leaves workflow rules on the old value), NDC-2867 (Replace refused when a custom view uses the value), NDC-2868 (save without version overwrites), NDC-2869 (two Arabic labels not translated).

  • Test spec: docs/crm-global-sets/spec-crm-global-sets.md in the QA repository.

  • The comparison changed nothing. Test runs used QA GS1111 data on NDC-Staging and in a Zoho test org; all of it was deleted afterwards.
