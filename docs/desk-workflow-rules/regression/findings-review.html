Desk Workflow Rules | Editing a rule cancels its pending scheduled actions

Steps to reproduce

  1. Create a workflow rule on Tickets, On Create, with a Field Update action delayed by 90 seconds.
  2. Create a ticket that matches.
  3. Within the 90 seconds, edit the rule (e.g. change the Field Update value) and save.
  4. Wait 2 minutes and open Execution History.

Expected

The pending action still runs (old or new version), or the editor warns that pending scheduled actions will be cancelled.

Actual

The pending action is Cancelled ("rule action … no longer exists") and nothing runs on the ticket. No warning when saving. Any edit of a rule silently drops every pending scheduled action.

Re-check
Pending action Cancelled ("rule_action … no longer exists"), nothing ran
Zoho (docs)
No Zoho equivalent. Zoho workflows have no scheduled actions ("no built-in delay or scheduling"); TAVI-only feature, judged on its own: pending actions are lost silently.
Evidence
FILED as NDC-3203 (23 Nov). Run 2, 22 Nov, NDC-Staging.

API-01Filed NDC-3230MediumRe-checked 23 Nov ✓

Desk Workflow Rules | A rule update that leaves out the conditions clears them, so the rule runs on every ticket (Zoho keeps them)

Steps to reproduce

  1. Take a rule with conditions (e.g. Subject starts with "QA").
  2. Save a change that sends only the actions (API PATCH with only actions).
  3. Create any ticket.

Expected

The conditions are kept, or the save is refused.

Actual

The conditions are cleared, the rule becomes "All tickets" and runs on every new ticket (6 unrelated tickets in the test).

Before filing

What the TAVI editor does (captured 23 Nov): an action-only edit sends the whole rule with its conditions; removing all conditions sends the rule with NO criteria key, and the API stores criteria = null (editor then shows "No conditions — actions run on every event"). Zoho (live, assignment rules): leaving the conditions out of an update KEEPS them; only an explicit criteria: null clears them. To match Zoho: the API should keep conditions when the key is missing and clear them only on an explicit null — and the editor must then send criteria: null when the user removes all conditions, or clearing in the editor will stop working.

Re-check
Partial save → conditions null (API only; the editor sends the full rule)
Zoho (live (assignment rule))
TAVI differs from Zoho. Zoho keeps the conditions when an update leaves them out (rename only, or agent only: conditions unchanged) and clears them only when they are sent explicitly as empty (criteria: null). TAVI clears them whenever they are left out. Checked live 23 Nov with Zoho assignment rules, which use the same condition format (workflow rules could not be created by API).
Evidence
FILED as NDC-3230 (23 Nov). Full ticket draft (not filed): api-01-ticket-draft.md. Run 1, 22 Nov.

Desk Workflow Rules | Text condition "is" is case-sensitive

Steps to reproduce

  1. Create a rule with Subject is "abc".
  2. Create a ticket with subject "ABC".
