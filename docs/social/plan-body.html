Test plan: scope, approach, environments, criteria, risks

Objective

Check that the TAVI Social module does what Zoho Social does for the features in scope, works with TAVI CRM and Desk, and is secure, reliable and usable before go-live. The reference is the Zoho Social study page (25 Nov 2026). Extra capability beyond Zoho is a plus, not a bug.

Scope

  • In: portal, brands and onboarding; channel connection; roles and permissions; composer; scheduling, queue, repeat, pause; bulk scheduler; approvals; posts, calendar and drafts; media, links and AI; publishing engine; Inbox; Messages; Monitor and Live Stream; Connections; Collaborate and notifications; Reports; CRM and Desk integration; settings and audit log; public API; security; performance; UI, Arabic/RTL, accessibility; end-to-end journeys.
  • Networks: cases are written for Facebook Page, Instagram, X and LinkedIn first. Run network-specific cases only for the networks the product owner puts in v1; mark the rest Skipped.
  • Out until confirmed: agency client portal and white-label, mobile apps, browser extension, MCP, link-in-bio, billing and plan purchase. C-12 and the plan-limit cases run only if those parts are built.

Approach

  • Expected results follow Zoho Social's documented behaviour. Where TAVI's requirements differ, the requirement wins and the case gets a comment.
  • Order: P0 cases of each area as features land (smoke), then P1, then P2. End-to-end journeys (area X) last, before sign-off.
  • Methods: manual in the browser for UI and network-side checks; API calls for permissions, validation and state machines; Selenium automation for regression (composer validation, approvals, inbox rules) once screens are stable.
  • Network-side proof: for every publish or reply case, confirm on the real network page, not only in TAVI.
  • Bugs: filed in Plane as "Social | <title>" with the case ID and evidence images; the case here is set to Fail with the ticket number.

Environments and test data

  • TAVI NDC-Staging with Social, CRM and Desk on one tenant, plus a second tenant for isolation cases.
  • Team-owned test accounts on each network: a Facebook Page with Business Manager and an ad account, an Instagram Professional account linked to it, an X account, a LinkedIn Company Page with a super-admin profile, and a second "customer" account per network to comment, DM and mention. Never a real customer page.
  • Users: Portal Admin, Brand Admin, User, Limited Publisher, one custom role, one approver, one user limited to a single channel.
  • Reference: the Zoho Social trial portal opened 25 Nov 2026, for side-by-side checks once a test channel is connected.
  • Test data names start with QA SOC; a ledger lists everything created; test posts are deleted from TAVI and the networks after each round.

Entry criteria

  • Feature deployed to staging with release notes; requirements available.
  • Network developer apps registered and test accounts connected.
  • P0 smoke of the area passes, otherwise the area is reported as blocked.

Exit criteria

  • All P0 cases pass; no open Urgent or High bugs.
  • At least 95% of P1 cases pass; the rest have agreed workarounds.
  • All end-to-end journeys (X-01 to X-05) pass.
  • Report numbers match the networks' own insights within the agreed tolerance.
  • Test data cleaned on TAVI and on the networks.
