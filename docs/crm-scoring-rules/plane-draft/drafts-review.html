Scoring Rules: features Zoho CRM has that CRM is missing

Gap liststate Backlog · links NDC-2030

Summary

We compared CRM's Scoring Rules with Zoho CRM (Setup › Automation › Scoring Rules, manual score). This ticket lists what Zoho has and CRM does not have yet. The work item for the feature is NDC-2030; it has no detailed spec, so every item below is "not in NDC-2030".

Already done in CRM

  • Settings › Automation › Scoring Rules per module: list, create, edit, delete, Active switch, empty state and the 50-rules-per-module limit with a banner.

  • Field rules: field, condition, value and points (−10000 to +10000, not 0), up to 25 per rule, for text, number, date, date-time, pick list, multi-select, checkbox, user and lookup fields.

  • One Score field, worked out on every save (form, inline, mass update, import, API, lead conversion, workflow field update); it cannot be typed by hand.

  • Score as a list column, sort, filter, export and in reports (column and filter); score changes in the record timeline.

  • Workflow trigger "On Score Change" (increases, decreases, either) and workflow conditions on Score.

  • Edit conflict check between two admins, permission checks in the API, audit entries, Arabic and right-to-left.

  • CRM also has things Zoho does not: a threshold on the score trigger ("only when it reaches 50"), scoring on any module (Tasks, Calls, Services…), a 120-character rule name and ±10000 points (Zoho: 25 characters, ±100).

Missing — building a rule

  1. Rule per layout. Zoho asks for a layout (one layout or All Layouts) when the rule is created. Today a rule covers the whole module.
  2. Which records a rule scores. Zoho has "Add Criteria under Leads Fields": only matching records are scored. Today every record of the module is checked.
  3. Several conditions in one scoring line, joined with AND/OR and an editable pattern ("Criteria Pattern (1 and 2)"). Today each line has one condition.
  4. More conditions: between and not between (numbers, dates), relative dates (Today, Current Month, Previous Week, Age in Days, Due in Days…), and contains / starts with / ends with on pick lists. Today the API answers "'between' is not a known operator".
  5. Channel (touch point) scoring: points for emails opened, clicked or bounced, calls, campaigns, Desk tickets, missed chats, surveys and social, with Add / Subtract and time windows ("more than 10 emails in the last 15 days"). Today the API answers "Only field rules can score a record; activity (touch point) scoring is not available".
  6. Clone a rule. Today the row menu has Edit and Delete only.
  7. Up to 30 conditions per rule (Zoho Enterprise; 50 on Ultimate). Today 25.

Missing — how scores are kept

  1. Update old records. When a rule is saved Zoho asks "Update old records?" and rescores records created or active in the last 6 months, and it has a Run Scoring Rules action. Today a record is scored only when it is saved again, so old records keep score 0.
  2. A separate score per rule. Zoho keeps each rule's score on the record (for example Web +10 and Quality −25 as two rows). Today there is one combined Score.
  3. Positive score and negative score (plus touch-point scores) next to the total. Today only the total.
  4. Score fields per rule: Zoho offers "Would you like to add score fields to the records? Yes, proceed" (label + score type), removed with the rule. Today there is one fixed Score field.
  5. Switching a rule off keeps the scores it already gave (Zoho). Today the points are dropped on each record's next save.
  6. Deleting a rule removes its scores at once (Zoho, without editing the records). Today old scores stay until each record is saved.

Missing — where users see scores

  1. Scoring Rules section on the record page: one row per rule with Positive, Negative, touch-point columns and Score. Today the record page shows no score at all, because Score is in no layout by default; only the timeline mentions score changes.
  2. Search and status filter on the rules list (Zoho: search box, All Modules filter, Status filter). Today there is only the module picker.

Missing — API

  1. Clone, run scoring rules (background job), per-rule scores of a record, activate and deactivate actions. Today the API has list, get, create, update, active and delete; /scoring-rules/recalculate, /stats and /export return 404.

Could not be checked

  • Web form leads: Leads has no web form on NDC-Staging. Please add one so we can test that web-form leads are scored.

Additional notes

  • Not gaps: Zia Score (Zoho's AI scoring is a separate feature); the extras listed above.

  • Bugs found in the same run are filed separately (see the comments).

  • Test sheet with all 149 cases and results: CRM Scoring Rules test sheet (Claude artifact) and docs/crm-scoring-rules/cases.js in the QA repository.

1. Scoring Rules | A field used by a scoring rule can be deleted, and the rule silently stops scoring

MediumCase K1 · B01-K1-deleted-field.html

Summary

A custom field that a scoring rule uses can be deleted with no warning. The rule keeps a condition on a field that no longer exists, the rules list shows nothing wrong, and records quietly lose those points on their next save. The rule can then no longer be saved.

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Owner account; Leads number field "QA SR1112 Num" used by rule "QA SR1112 K1" (QA SR1112 Num ≥ 5 → +9)

Steps to reproduce

  1. Create a Leads number field and a scoring rule "field ≥ 5 → +9".
  2. Create a lead with the field = 6. Its Score is 9.
  3. Delete the field in Modules and Fields.
  4. Save the lead again, then open the rule in Scoring Rules.

Expected result

As in Zoho CRM, the delete is refused while the field is used: Zoho answers "The custom field has already used in other places". At the least, CRM should warn the admin and mark the rule as broken.

Actual result

  • The field is deleted (204) without any warning.
  • The rule list still shows the rule as normal, with 1 entry and +9.
  • The lead's Score drops from 9 to 0 on its next save.
  • Opening the rule shows an empty field; Save fails with "This field is not in the module."

Notes

  • Test data deleted after the check.
  • Evidence: K1-deleted-field-rule-vs-zoho.png (TAVI rule editor left, Zoho refusal right).

2. Scoring Rules | Removing a pick list value used by a scoring rule gives no warning, and records lose their points

LowCase K2 · B02-K2-removed-value.html

Summary

A pick list value that a scoring rule uses can be removed from the field with no warning. The rule still stores the old value, the editor shows the value as empty, and records that hold the value lose their points on their next save.

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Owner account; Leads pick list "QA SR1112 PL" (Alpha, Beta); rule "QA SR1112 K2" (PL is Alpha → +4)

Steps to reproduce

  1. Create the pick list and the rule "PL is Alpha → +4".
  2. Create a lead with PL = Alpha. Its Score is 4.
  3. Edit the field and remove Alpha from the values.
  4. Save the lead again, then open the rule.

Expected result

The admin is warned that a scoring rule uses the value. In Zoho CRM a removed value moves to "unused" and the rule keeps its condition.

Actual result

  • Alpha is removed (200) with no warning.
  • The lead's Score drops from 4 to 0 on its next save.
  • The rule still stores "Alpha"; the editor shows "QA SR1112 PL is" with an empty value.

Notes

  • Test data deleted after the check.
  • Evidence: K2-removed-value-rule-vs-zoho.png.

3. Scoring Rules | Users without permission see the page, the New button and the editor, then every call is refused

LowCases A2, A6 · B03-A2-no-permission-screen.html

Summary

A CRM user who may not manage scoring rules still gets the Scoring Rules menu item, the page, an active New Scoring Rule button and the full editor. Every API call is then refused with 403. The page and the API check different permissions.

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Account Mahmoud Samy (CRM User profile)

Steps to reproduce

  1. Sign in as the CRM User.
  2. Open Settings › Automation › Scoring Rules.
  3. Click New Scoring Rule and open the Field list.

Expected result

A user without the permission does not see the menu item, or sees a no-access page. In Zoho CRM scoring rules need the Manage Automation permission.

Actual result

  • The menu item and page open. The list says "The scoring rules could not be loaded — You don't have permission to manage scoring rules for this module."
  • New Scoring Rule is enabled and opens the editor with the full field list.
  • The API refuses list, create, update, activate and delete with 403 PERMISSION_DENIED, so no data leaks.
  • The page route is guarded by the Modules and Fields manage permission (metadata.modules.manage), while the API uses a different check. There is no separate scoring-rules permission in Profiles.

Notes

  • Evidence: A2-lowpriv-page-and-editor.png.

4. Workflow Rules | Score threshold accepts text or decimals with no message and keeps the last valid number

LowCase G9 · B04-G9-threshold-input.html

Summary

In a workflow rule with the "Score value" trigger, the threshold box accepts "abc", "12.5", an empty value or a huge number. The box is marked invalid but no message explains why, and Create still goes on, silently keeping the last valid number.

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Owner account; new workflow rule on Leads (not saved)

Steps to reproduce

  1. Workflow Rules › New, module Leads, Next.
  2. Pick "Score value", tick "Only when it reaches". The box shows 50.
  3. Type -20, then replace it with abc.
  4. Click Create.

Expected result

A clear message ("Enter a whole number") and Create blocked until the value is valid.

Actual result

  • Empty, abc, 12.5 and 999999999999999999 are marked invalid (red) with no message; -20 is accepted.
  • With abc in the box, Create opens the next step and the summary reads "This rule will be executed when the score of a record in Leads rises to -20 or more".

Notes

  • The draft rule was cancelled, nothing was saved.
  • Evidence: G9-threshold-invalid.png.

5. Scoring Rules | A save without a version overwrites the rule with no conflict check

LowCase H2 · B05-H2-no-version-overwrite.html

Summary

PUT /scoring-rules/{id} is accepted without row_version and overwrites the rule. Another admin's change can be lost without warning. The screen sends row_version and is protected; any other client is not. This is the same problem as NDC-2868 (Global Sets).

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Owner account, API

Steps to reproduce

  1. Create a rule (points 1) and save it with points 5 and the current row_version (200, version 2).
  2. Send PUT with points 3 and no row_version.

Expected result

The save is refused because no version was sent, the same way a stale version is refused with 409 SCORING_RULE_VERSION_CONFLICT.

Actual result

  • 200; the rule now has points 3. A stale row_version is refused correctly (409), only a missing one is not checked.

6. Scoring Rules | Two creates at the same moment make two rules with the same name

LowCase H4 · B06-H4-duplicate-names.html

Summary

The duplicate-name check is not safe when two create requests arrive together. Both succeed and the module ends up with two rules of the same name.

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Owner account, API

Steps to reproduce

  1. Send two POST /scoring-rules requests for Leads with the same name at the same time.
  2. List the Leads rules.

Expected result

One rule is created and the other request is refused: "This module already has a scoring rule named …" (the answer a single second create gets).

Actual result

  • Both return 201 and the list shows two rules named "QA SR1112 dbl".

Notes

  • A double click on Create in the screen did not reproduce it; this is an API race.

7. Scoring Rules | The same condition twice in one rule is accepted and counted twice

LowCase C19 · B07-C19-identical-conditions.html

Summary

A rule can hold two identical lines (same field, condition, value and points). Both count, so a matching record gets double points.

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Owner account

Steps to reproduce

  1. Create a Leads rule with two lines: Lead Source is chat → +3, and again Lead Source is chat → +3.
  2. Create a lead with Lead Source = chat.

Expected result

The rule is refused as in Zoho CRM: ALREADY_USED "The criteria is already given in the same rule under different index".

Actual result

  • The rule is saved (201) and the lead scores 6 instead of 3.

8. Scoring Rules | The API saves conditions the screen cannot show (regex, length, any value on User fields)

LowCases I6, D15 · B08-I6-D15-api-conditions.html

Summary

The scoring-rules API accepts conditions that the editor does not offer and cannot display: regexMatches, lengthEq and isEmpty on text fields, and "is x" on a User field with a value that is not a user. Such rules score records, but an admin opening them in the screen cannot see or fix the condition.

Environment

  • Staging, staging-crm.taviportal.com, tenant NDC-Staging, 12 Nov 2026
  • Owner account, API

Steps to reproduce

  1. POST /scoring-rules with an entry {field_key: company, operator: regexMatches, value: "Acme.*", points: 1}.
  2. Create a lead with Company "Acme Ltd".
  3. POST a rule with {field_key: user, operator: eq, value: "x", points: 1}.

Expected result

Only the conditions the editor offers per field type are accepted (text: is, is not, contains, doesn't contain, starts with, ends with, is empty, is not empty; user and lookup: is empty, is not empty), and values are checked against the field.

Actual result

  • regexMatches, lengthEq and isEmpty are saved (201) and score records ("Acme.*" matches Acme Ltd).
  • "user is x" is saved (201).
  • A free regex from the API is also a slow-query risk.
