CRM Scoring Rules, explained

What the feature is for, how it works in TAVI, and how it differs from Zoho CRM. Written 12 Nov 2026 from the TAVI build on NDC-Staging and Zoho's documentation.

The business idea

A sales team has more leads than it can call. Scoring gives each lead a number that says how promising it is, so people call the best ones first. The admin decides what "promising" means by writing rules: a lead from the website gets points, a lead in the target industry gets more, a lead marked Junk loses points.

  • Sales sort or filter by score ("Hot leads: score 30 or more").
  • Marketing sees which sources bring good leads.
  • Automation reacts when a score passes a line, for example creating a call task for the owner when a lead reaches 30.

A worked example

The score is the sum of every line the record matches, across all active rules of its module.

How TAVI does it

  • Where: Settings › Automation › Scoring Rules. Pick a module, then add rules.
  • A rule has a name, a description, an Active switch and up to 25 "field rules". Each field rule is one field, one condition (is, contains, greater than, is empty…), a value and points from −10,000 to +10,000 (not 0). A module holds up to 50 rules.
  • The result is one system field called Score on Leads, Contacts, Deals and Accounts.
  • When it changes: each time a record is saved, TAVI adds up the points of every active rule and writes the Score. A new or changed rule does nothing to old records until they are saved again.
  • Automation: a workflow rule can start "On Score Change" — when the score goes up, goes down, or crosses a number such as 50.

How it works technically

  • The screen talks to /api/v1/scoring-rules: list by module, read one, create, update (with a row_version so two admins cannot overwrite each other), switch active on/off, delete.
  • A rule is stored as a list of entries: field_key, operator, value, points.
  • On every record save the server evaluates the entries against the record and writes the total into the score field. The score is computed, so users should not be able to type it.
  • If the score changed, the workflow engine gets a RecordScoreChanged event with the old and new value, which is how the "crosses 50" trigger works.

TAVI compared with Zoho CRM

Same idea

  • Rules per module that add or subtract points for field values.
  • Active / inactive, edit, delete.
  • Workflow when the score changes.

Zoho has more

  • Points for customer actions (emails opened, calls, campaigns, tickets, chats), not only field values.
  • Can rescore old records straight away.
  • Separate score per rule, plus positive and negative scores.
  • Rule per layout, filter for which records a rule scores, AND/OR conditions, clone.
